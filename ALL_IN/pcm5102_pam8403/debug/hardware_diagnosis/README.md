# 无声问题诊断文件

## 2026-10-13：先处理异常发热和压力 AO 接线

用户报告主工程下载后 FPGA 主芯片几秒内明显烫手，并确认压力模块 AO 直接连接 FPGA、没有分压。**保持断电，先断开压力 AO；未完成下面的接线和电压核对前，不要运行下载脚本或继续试听。**

用户随后补充这次没有烧录、没有接外设，并进一步确认“仍烫”指的是**断电后仍有余热**。这不能作为“冷却后空载上电仍迅速发热”的证据，也不能证明芯片已损坏；完全断电后芯片和 PCB 需要时间自然冷却。目前原先上电几秒内明显烫手的原因仍未确认。先断开所有 USB 和其他供电，等待自然冷却，不要求用户为确认而再次上电。此前下载的是 SRAM 还是外部 Flash 尚不明确；本次没有重新烧录不等于上电时没有加载旧程序。

当前 `gowin_fsr_adc.v` 使用片内 ADC 的外部 PAD 模式，CST 用 `USE_ADC_SRC bus0 IOT56;` 选择输入。ADC 单端输入量程为 **0～1V**，并不因为其他数字接口是 3.3V 就能直接接 3.3V AO。原厂依据：[Gowin ADC 用户指南，2.3.2 节表 2-3](https://cdn.gowinsemi.com.cn/UG299E.pdf)。这是测量量程；目前没有测得实际 AO 电压，也没有确认器件的受损情况，不能把超量程直接当成已经烧坏的证明或发热的唯一原因。

断电后按当前工程接线：

```text
压力模块 AO ── 22kΩ ──┬── J3 物理第36脚 / FPGA J8（ADC 正端）
                      │
                     4.7kΩ
                      │
                     GND

J3 物理第35脚 / FPGA K8（ADC 负端）── GND
模块 GND、分压下端和 FPGA GND 共地。
```

这组电阻以 AO 最大不超过 5V 为前提：AO=3.3V 时分压中点约 0.58V，AO=5V 时约 0.88V。不是仅串联一只电阻。先让 AO 与 FPGA 断开，按模块额定电压独立供电，用万用表测未按、轻按、重按时的 AO 和分压中点；确认整个工作范围分压中点不超过 1V 后，才允许接回 ADC。FPGA 断电时也不要让外部模块通过信号线向它送电。代码里的数字饱和以及 `FSR_ENABLE=0` 都不能保护模拟引脚；后者只旁路压力表达，并未移除 ADC 实例或引脚配置。

还需核对 TTP229 OUT1 的实际接线：当前应接 **J3 第5脚 / K4**，不能仍接 **J3 第2脚 / K1**。K1 已用于 FPGA 输出 PCM5102 LRCK，外部 OUT1 若也接此处，会造成两个输出相互驱动，可能影响声音并增加电流。

先纠正接线，再继续诊断；若断开外部模块的信号及供电连接后仍迅速异常发热，应停止上电，检查供电和板卡，不能靠反复烧录解决。本次只核对源代码、引脚约束和原厂量程要求，尚未测量板上电压、温度或电流，也没有执行新的下载。下文试听与采集流程仅适用于上述问题已排除、板卡无异常发热时。

这组文件用于区分“播放链路没有声音”和“当前整合版按键/音源/混音没有产生数据”。当前主工程的S1与触摸联合RTL仿真已通过，但本次尚未在实物上确认根因，不能用仿真结果直接判定硬件或top一定正确。

## 自动下载并核对配置

完成上面的接线、电压及发热核对后，接好FPGA供电与下载USB，在本目录运行：

```powershell
./download.ps1
```

默认下载持续音版。脚本自动查找下载器通道A及其USB位置，先扫描目标FPGA，再执行SRAM下载和UserCode读回。只有打印`SUCCESS: SRAM programmed; UserCode verified`才完成这次配置核对。安装路径不同可传入`-ProgrammerDir <Programmer/bin路径>`；有多个下载器时用`-CableLocation <位置>`指定目标。

下载整合版GAO：

```powershell
./download.ps1 -Bitstream 02_current_top_gao.fs
```

操作记录保存在`download_cables.log`、`download_scan.log`、`download_program.log`和`download_verify.log`。脚本不会自动改用FTDI的另一通道。

## 1. 先试听持续音

在Gowin Programmer中选择本目录的 **`01_continuous_440hz.fs`**，执行 **SRAM Program**。下载完成后无需按任何键，应持续输出约440Hz测试音，数字幅度为1/16。BCK/LCK/DIN仍使用K2/K1/L1，即J3第1/2/3脚。

- **能听到持续音**：本次配置与当前接线下，DAC、功放和喇叭可以播放。接着检查整合版的按键门控和音源数据。
- **仍无声音**：暂时断开TTP229、压力和手势的信号线，保留FPGA→DAC→功放→喇叭的接线，再试一次。如果此时出声，重点核对新增传感器是否占用了音频引脚。
- 如果旧的可用工程在完全相同接线下能出声，而此文件不能，记录旧工程的名称和下载文件，继续比较其引脚、时钟和DAC接口格式，不能仅凭这一项判断模块损坏。

## 2. 观察当前整合版

下载 **`02_current_top_gao.fs`** 到SRAM。该版本保留当前触摸、压力、手势和S1吉他，只追加观测寄存器。它不会自动播放持续音。

在Gowin Analyzer Oscilloscope中打开配套的 **`02_current_top_gao.gao`**。此工具使用FPGA内部逻辑分析仪，电脑通过板子的下载USB即可采集，不需要外接示波器。

1. 下载后等待至少1秒。
2. 松开S1，再按住约50ms，然后Start并Force Trigger。不要等几秒才采，因为吉他会自然衰减。
3. 再采一份“松开S1、按住触摸OUT1”的数据。
4. 导出CSV，时钟周期20ns，时间单位ns。两次数据用不同文件名。

| 信号 | 要确认的内容 |
| --- | --- |
| `resetn` | 启动后是否为1 |
| `key_s1` | 按下是否为1、松开是否为0 |
| `touch_out` | 触摸后物理输入位是否变化 |
| `touch_ready` / `touch_keys` | 启动等待是否完成、消抖后相应键是否为1 |
| `guitar_scaled_sample` / `touch_mix0` | S1吉他/触摸音源是否有非零样本 |
| `fsr_gain` | 默认压力增益是否在16384～65535范围内；它不控制S1吉他 |
| `gesture_ready` / `gesture_sample` | 手势初始化和音源状态 |
| `audio_sample` | 最终混音是否有非零数据 |
| `i2s_bck` / `i2s_lrck` / `i2s_din` | 发送时钟和串行数据是否活动 |

所有观测寄存器统一比原信号晚20ns。音频总线应按16位有符号数显示。采集窗口只有81.92us，约4个音频帧，样本在帧间保持不变是正常现象。默认S1边沿触发发生在5ms消抖之前，因此请按上述方法在按住之后强制触发。

判读顺序：**原始按键 → 消抖后的门控 → 对应音源PCM → 最终混音PCM → I2S**。这样可以定位故障在哪一级，而不是反复猜测和改动所有模块。

完整探针、源码和构建脚本保存在当前工程的`debug/integration_gao`目录。下载和采集步骤均已列在本说明中。

## 接线与下载核对

| J3物理脚 | 当前逻辑用途 |
| --- | --- |
| 1 / K2 | PCM5102 BCK |
| 2 / K1 | PCM5102 LCK/LRCK |
| 3 / L1 | PCM5102 DIN |
| 5 / K4 | TTP229 OUT1 |
| 23 / H4 | APDS SCL |
| 24 / G4 | APDS SDA |

K1不能同时连接TTP229 OUT1和PCM5102 LCK。SRAM下载后保持供电再测试；断电后SRAM配置丢失，可能重新加载Flash中的其他工程。

如果同一套DAC/功放/喇叭在旧版本可用，先保留其已验证的配置。当前代码没有MCLK输出：PCM5102芯片的SCK需保持低，XSMT需为高以解除静音，FMT需为低以选择I2S。模块可能已有电阻或焊盘设置，按实际电路确认，不能仅根据H1～H4名称猜测。原厂依据：[TI PCM510xA数据手册，引脚表和9.3.5.3节](https://www.ti.com/lit/ds/symlink/pcm5102a.pdf)。
