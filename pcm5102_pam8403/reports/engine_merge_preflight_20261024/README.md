## 测量结果

| 场景 | 周期 | 余量 |
|---|---:|---:|
| 32 声部，无事件 | 535 | 489 |
| 32 声部，TEST32 | 889 | 135 |
| 32 声部，32 条独立事件 | 951 | 73 |
| 16 触摸声部，无段转换除法 | 756 | 268 |
| 16 触摸声部同时段转换 | 1012 | 12 |

周期包含接受 `sample_ce` 的时钟沿及发布结果的时钟沿。新用例每个被测窗口严格执行 1024 个时钟；28 个窗口全部完成，没有正常场景 overrun。攻击、衰减和释放共命中三帧“16 声部各 16 拍除法”，每帧 DIVIDE 计数 256。

用例在部分窗口之间预装事件队列，并非连续运行的顶层 I2S/UART 压力测试。它验证单次帧 deadline 和模块行为；连续触摸音频与频谱另由现有 `tb_touch_tdm_synth` 覆盖，已有顶层联合压力证据见 `FX_PREFLIGHT_20261024.md`。

传感器公式 `16×V + 11×E + 2×C + 23` 在本轮全部被测窗口成立，首次 `VOICE_PRIME` 为 17 拍；触摸公式为 `756 + DIVIDE周期数`。48 声部与不同事件配额的数字仍是方案推算。

## 行为结果

- 正弦表 256 点全部满足 `sensor[i] == touch[4*i]`。
- TEST32 实际完成 32 次分配，逐槽检查 32 个不同的规定频率增量。
- 传感器池满时 32 条新事件替换原最老槽，未触发 overrun；现有 `tb_tdm_queue` 同样通过 FIFO64、替换、快照和故意溢出诊断。
- 16 个物理键持续按住、`poly_limit=1` 时，触摸全部保持 active，未选出 victim。释放后全部回到静音状态。
- `tb_runtime_adsr` 通过 0～1000 ms 共 1001 档参数转换、sustain 映射、恢复配置、旧音快照及攻击中途松键验证。
- `tb_touch_tdm_synth` 通过 16 键相位增量、4096 采样频谱、独立包络/快照/释放和动态音高验证。

旧用例编译时存在默认关闭功能对应的悬空输入警告、timescale 继承及数组组合敏感性提示，仿真无失败。FIFO 故意溢出与故意错过 deadline 属于 `tb_tdm_queue` 的负例，不能要求这些负例的 overrun 为零。
