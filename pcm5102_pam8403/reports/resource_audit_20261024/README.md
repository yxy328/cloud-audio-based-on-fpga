# FPGA 资源诊断与隔离实验（2026-10-24）

本目录针对“合并引擎省 DSP 却增加 Logic、无法布通，下一步如何优化”进行审计。
生产 `src/`、默认工程、交付位流均未由本次实验修改；候选代码、仿真和构建使用独立副本。

**最终结论：尚无可交付的新优化。** APDS 精确缩位候选整机减少 151 Logic、62 CLS、2 DSP，但布局布线失败（460 条未布线网络）。
它证明了低成本缩小乘法原语的方向；未证明整机可用，也未解决 CLS/布线余量问题。保留原有已布通基线。

| 构建 | Logic | CLS | Register | BSRAM | DSP | 未布线 | 时序 |
|---|---:|---:|---:|---:|---:|---:|---|
| 原基线 | 21603 | 11326 | 10461 | 47 | 26.5 | 0 | setup/hold +0.083/+0.152 ns |
| APDS 精确缩位候选 | 21452 | 11264 | 10459 | 47 | 24.5 | 460 | 布线失败，无法验收 |
| 差异 | -151 | -62 | -2 | 0 | -2 | — | — |

即使 CLS 少 62，其占用仍约 97.8%。这组结果也说明资源数减少不保证布线成功。
综合层级 LUT＋ALU 减少 153，布局布线 Logic 减少 151；口径不同，并非数据矛盾。
整机收益亦包含未改动模块的映射变化，不能把全部减少量算作 APDS 局部电路缩小量。

## 1. 先确定真正的容量瓶颈

已布通基线为 `engine_share_base_20261024`：

| 指标 | 使用 | 总量 | 剩余 |
|---|---:|---:|---:|
| Logic | 21603 | 23040 | 1437 |
| CLS | 11326 | 11520 | 194 |
| Register（含 I/O FF） | 10461 | 23280 | 12819 |
| BSRAM | 47 | 56 | 9 |
| DSP | 26.5 | 28 | 1.5 |

Setup / hold WNS 为 +0.083 / +0.152 ns，未布线网络数为 0。
**CLS 使用率约 98.3%，因此下一轮的首要目标是可布通的 CLS 净下降。**
DSP 和 BSRAM 的减少分别记录，不能抵扣 CLS 的增加；通过 RTL 用例也不能代替布局布线验收。

## 2. “增加 709 Logic”不能全部归因于共享模块的多路选择器

比较原始基线与 `engine_merge_candidate_20261024_01` 的 `*_syn_rsc.xml`，只取模块自身的 `Lut + Alu`，不累加包含子模块的 `T_*` 字段：

| 层级 | 自身 LUT＋ALU 增量 |
|---|---:|
| Flash 录制存储 `take_enabled.u_store` | +257 |
| APDS 控制器 `u_gesture/u_ctrl` | +104 |
| 新共享算术 `shared_synth.u_arithmetic` | +99 |
| 歌曲下载 `u_keymap/u_download` | +87 |
| HC05 命令控制 `u_keymap` 自身 | +72 |
| Touch synth 自身 | -31 |
| Sensor synth 自身 | -32 |

其中 Flash、APDS、歌曲下载三份源代码在两个冻结构建中的 SHA256 完全相同。
因此，证据支持“修改引发了更广泛的综合/映射变化”，还不足以证明具体由哪个优化阶段造成。
共享算术与两路 synth 的自身增量合计仅 +36；其他增量不能简单记到仲裁器头上。

注意：这里是综合资源统计，整机 +709 是布局布线报告中的 Logic 差异，二者不是完全相同的统计口径。
机器可读的完整层级表及源文件校验见 `hierarchy_audit.json`。

## 3. 两类小实验及实测结果

使用同一 Gowin V1.9.11.03 Education、GW5A-LV25MG121NC1/I0，`resource_sharing=1`、`retiming=1`、`global_freq=50`。
独立模块综合保留所有输出，因此以下绝对数不能直接与整机裁剪后的模块计数混算。

| 独立模块版本 | LUT | ALU | 合计 | FF | 主要乘法原语变化 |
|---|---:|---:|---:|---:|---|
| 歌曲基线 | 1334 | 128 | 1462 | 526 | 无 |
| 歌曲共用固定译码 | 1362 | 128 | 1490 | 526 | 无 |
| APDS 基线 | 964 | 547 | 1511 | 543 | 2×MULT27X36 |
| APDS 仅缩为 18 位幅值 | 968 | 544 | 1512 | 539 | 仍为 2×MULT27X36 |
| APDS 精确 17 位幅值 × 18 位比例 | 976 | 543 | 1519 | 539 | 改为 2×MULTALU27X18 |

### 歌曲译码：淘汰

把七路动态选位和动态掩码写入改为共享固定音高比较矩阵。
51,488 组译码向量全部一致，覆盖每路所有 256 种映射字节、每个掩码位、所有 8192 种和弦掩码及随机混合映射。
原歌曲测试同时运行新旧模块，逐拍比较全部公开输出，通过原子换库、和弦/休止符、预读、背压、停止/重启及 128 条密集音符测试。
**但 LUT 增加 28，因此不进入生产工程。代码看起来共用得更多，不代表映射更省。**

### APDS 幅值缩位：有可证明的 DSP 映射收益

第一组、最后一组的两路通道分别为 `Fu,Fd,Lu,Ld`，各自位于 0..255：

```text
delta = (Lu-Ld)*(Fu+Fd) - (Fu-Fd)*(Lu+Ld)
      = 2*(Lu*Fd - Ld*Fu)
|delta| <= 2*255*255 = 130050 < 2^17
scale <= (255+255)^2 = 260100 < 2^18
strength <= 130050*260100 = 33826005000 < 2^35
```

因此 delta 需要 18 位有符号数，但它的绝对值只需要 17 位无符号数；scale 用 18 位，strength 用 35 位。
该证明覆盖实际饱和门限 250 之外的整个 8 位通道范围，没有截掉合法精度。
仅将幅值设为 18 位时乘法原语不变；继续缩到有数学保证的 17 位后，综合才切换为较小乘法原语。

50,256 组端点元组通过新旧 RTL 对比，包括八个独立通道的全部 256 个 0/255 边界组合及 50,000 个随机组合。
逐项核对 delta、scale、strength、方向以及上报时钟；已有 APDS NACK/重试测试也通过。
该测试直接注入方向计算阶段，不等同于完整 I2C 手势场景或硬件回归。

候选产生两条 18→17 位截断提示，正是上述已证明幅值上界允许去掉的最高位；不依赖有损音频量化。
候选不添加仲裁器、不改变状态机节拍。局部 LUT＋ALU 增加 8，是否带来整机收益以全工程报告为准。

## 4. 下一轮优先路线

基线综合中占用较大的控制模块包括：HC05 自身 1935、录制时间线自身 1525、APDS 自身 1463、歌曲下载自身 1455、Flash 存储自身 1369 个 LUT＋ALU。
这些数用于排查优先级，不是可回收资源数量。

1. **优先做慢速控制模块内部的局部串行化。** APDS 的四路平均值计算目前并行使用加减/比较路径，且方向计算只在一次手势结束时运行。可尝试共用一条局部运算通路；先明确允许的报告延迟，再验证分类结果、释放保护、校准和异常恢复。不要接入音频 DSP 的跨模块仲裁。现有平均值算法已是迭代减法，不能再把“删除组合除法器”当收益来源。
2. **Flash 控制器逐个检查宽选择器和寄存器写入条件。** 128 位 header 的动态字节选择和多处更新值得单独做 A/B；CRC 已经串行运行，不能重复承诺串行 CRC 的收益。所有修改必须保留擦除授权、两槽选择、CRC、最后写 commit 字节及掉电恢复语义。
3. **录制状态存储审查大宽度快照与播放寄存器。** 当前有 528 位原子快照和 528 位播放状态。要先证明何时可串行访问、如何保持原子性，再讨论移到 BSRAM；仅声明成数组并不会自动省 LUT，也不能拆坏同一时刻的状态快照。
4. **编码和综合选项作为单变量实验。** 只对一个低速控制 FSM 比较保留/去除 onehot 属性；不要承诺二进制编码必省 CLS。现有工程已启用 resource_sharing 和 retiming，继续“打开共享”并不是新优化。

若希望回收大量 CLS，需要减少实际并行数据通路、宽度和访问端口；仅整理命名、合并源文件或反复更换布局策略无法保证面积收益。

建议第一阶段工程目标为净减少至少 500 CLS（不是预测），验收同时要求完整布线、setup/hold 无违例、功能和帧预算通过。
较小但真实的收益也可保留；任何新增失败或资源互换必须明确单列。

## 5. 实验验收顺序

冻结输入及工具参数 → 单项修改 → 对应功能/等价检查 → 独立综合初筛 → 全工程同条件综合/PnR → 比较 Logic/CLS/FF/BSRAM/DSP/未布线数/WNS → 最后才推广到生产与全量回归。
面积无收益的候选在初筛阶段淘汰，避免每次先跑全部用例后才发现装不下。
仿真 PASS 数不作为资源优化完成的指标。

官方资料也说明资源复用可能增加逻辑级数和路径延迟；本报告中的具体资源数字均来自本地构建，不是手册估算：
[Gowin FPGA Design Guide，4.3.1](https://www.gowinsemi.com/upload/database_doc/38/document/5b923e5ef105f.pdf)、
[GowinSynthesis User Guide](https://cdn.gowinsemi.com.cn/SUG550E.pdf)。
