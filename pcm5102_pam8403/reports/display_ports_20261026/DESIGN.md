# 显示读口结构实验（2026-10-26）

本轮从第一轮 HC-05 已接入的生产输入开始，基线为 Logic 22447、CLS 11387、Register 10732、BSRAM 53、DSP 26.5。历史 83 CLS 收益不计入本轮。

## 端口下界与实现选择

原模块有一份插入 RAM 和六份显示镜像，每份 64×7。插入流水线每拍可接收一个新音符，独立同步读口提前取得下一拍的旧值，写端口提交 OR 合并。这个读口不能在密集输入时随意让给显示。

显示上下半屏各需连续三行，但相邻时钟所需的三行窗口高度重叠。对每个半屏维护三个**未裁剪的原始行数据**，每拍只读窗口中新进入的一个端点，其余两行保留。每一份 RAM 仍是一写一读，整个结构保留三份 64×7 RAM，并非将七份数组直接合并成一个普通双口 RAM。

设当前上半屏物理首地址为 `head_top + scan_row`，下半屏相差 32。窗口含首地址、首地址减一、首地址减二。令 `advance = state == S_LATCH_LOW`。

| 当前边沿 | 下一窗口相对旧窗口 | 新读端点 | 保留数据 |
|---|---|---|---|
| 不滚动、不换行 | 0 | 下一首地址 | 旧第 1、2 项 |
| 滚动、不换行 | -1 | 下一首地址减二 | 旧第 1、2 项 |
| 换行、不滚动 | +1 | 下一首地址 | 旧第 0、1 项 |
| 换行且滚动 | 0 | 下一首地址 | 旧第 1、2 项 |

普通换行的首地址加一，滚动的首地址减一；两者同拍抵消。第 31→0 扫描行需要先交换上下半屏的原始窗口：例如旧下半屏首地址为 `head_top+63`，加一后恰为新上半屏的 `head_top+0`。再按同样的位移表处理即可。这也是原始缓存不能提前按可见 y 裁剪的原因。

## 同步读与写冲突

每个窗口由一个同步 RAM 输出和两个保留寄存器组成，`bottom_q` 记录 RAM 输出对应首端还是末端。新读地址与本拍写地址相同，则禁用物理读，下一拍使用显式锁存的 `write_previous`。被保留的两行也逐拍比较写地址并转发 `head_write_data`；只处理 RAM 输出冲突不足以维持密集写入的正确性。

三个 tap 的有效性继续使用原有逐拍语义：当前有效位、滚动清除、同拍写入优先、播放/复位和 y=0..54 裁剪。无效缓存中的旧数据不会直接显示；该地址重新有效必须来自写入，写入会同时更新 RAM、读转发或保留寄存器。STOP/reset 清除有效位，启动不需要扫描清空 RAM。

插入 RAM、音符距离/商流水线、接收条件、overflow、扫描状态机、视觉/状态读地址、RGB5 PWM 和模式切换边界均保持原结构。扫描仍每行 133 拍，每像素准备一拍、移位一拍。

## 核验与证据约束

`baseline/` 为本轮冻结的实际生产输入；`production_before/` 保存显示源码和原综合/PNR 输出；`window3/` 是独立候选，唯一生产输入差异为显示 RTL。`freeze.json`、各构建 `sources.json` 和退出记录用于防止源码或工具漂移。

`window3` 的 place1 构建最终有 221 条未布通网络，未采用；`window3_place2` 保持全部 RTL/ROM/约束和综合设置，只将物理放置改为 place2，完整通过后接入。实际综合选项除输出路径外一致，层级资源属性也一致；各物理构建独立核验。最终释放 4 BSRAM，整机 CLS 增加 77，仍保留 35 CLS 安全余量。结果包含 RTL 与物理策略的联合影响，不作纯 RTL 的 CLS 收益归因。

功能验证包含旧寄存器参考的逐拍比较、当前七 RAM 参考的逐拍比较、扫描/PWM/延迟算术测试、视觉和状态页面以及整机音频/TAKE 回归。覆盖稀疏真实毫秒节拍、连续节拍、无节拍、随机节拍、128 拍连续输入、重复 OR 合并、读端冲突、保留行写转发、环形地址回绕、31→0 换行、STOP 和 reset。仿真不是任意内部状态的形式等价证明。

旧扫描测试末尾直接注入六个旧镜像，需将该测试夹具改为注入两份新镜像，并按当前地址初始化两个缓存，保留全部原断言及裁剪行图样。最初的层级名编译失败日志保留。视觉/状态旧测试需要 `sim/build/` 图片输出目录，初次缺目录的失败日志同样保留；这些均不算功能通过证据。

只有完整布通、setup/hold 均通过且保留至少 35 CLS 余量的候选才可接入。BSRAM 释放量与新增控制 CLS 分别报告，不将局部 RAM 数量或综合网表 LUT 直接折算为整机收益。本轮不迁移其他存储，释放的 RAM 留作后续独立实验预算。
