## 2. 网上建议如何对应本工程

用户提供的 [CSDN 链接](https://blog.csdn.net/weixin_29170327/article/details/159334581)无法直接抓取正文。只能确认用户链接所带摘要中的 REG FIFO、RAM 实现和资源优化方向；下面技术结论以高云官方手册和本地证据为依据，不声称已核读该文章全文。

### 存储映射

[GowinSynthesis SUG550](https://cdn.gowinsemi.com.cn/SUG550.pdf) 第 5.16 节区分 registers、block_ram 和 distributed_ram。属性用于指导映射，最终仍须检查实际综合原语和 PNR 资源；读延迟、端口数、复位写法和同址读写行为必须满足目标存储器要求。

REG FIFO 通常会带来数据寄存器、地址选择和控制开销；深缓存优先评估 BSRAM，小缓存比较 REG/SSRAM/BSRAM 的完整成本。[UG285 存储器手册](https://cdn.gowinsemi.com.cn/UG285.pdf)说明 SSRAM 使用 CFU 的 LUT 实现，因此 distributed_ram 仍消耗逻辑资源，不能当作免费资源。BSRAM 的读模式和冲突行为也必须由调用方正确处理。

本工程 UART RX FIFO 已采用同步读，综合层级 `u_keymap/u_uart` 已有 1 个 BSRAM；实时按键 FIFO 已映射 SSRAM。命令缓存/字典、回复 ROM、TDM FIFO/上下文、TAKE 事件和三效果音频历史也已有 RAM/ROM 映射。`performance_logger.v` 虽然有较宽 FIFO，但 `hc05_keymap.v` 只在 `!ENABLE_EVENT_TAKE && !ENABLE_FLASH_AUDIO` 时生成该实例；默认 top_unified 启用 EVENT_TAKE，因此综合层级没有该日志实例，优化它不能预先算作默认位流收益。

### CLS 装箱、复位与使能

[GW5A DS1103](https://cdn.gowinsemi.com.cn/DS1103.pdf) 第 2.2 节给出每 CLS 的两个 LUT4 和两个寄存器结构。[SUG113 设计优化手册](https://cdn.gowinsemi.com.cn/SUG113E.pdf)说明共享时钟使能、状态编码和物理实现选项的影响。由此应同时观察 LUT/ALU、控制信号兼容性和实际 CLS；删除若干 FF 或减少若干 LUT，并不保证 CLS 同比例下降。

可以检查重复局部复位、细碎 CE、宽多路选择器和高扇出译码。仅对有效标记已经屏蔽的内部暂存数据考虑简化复位，必须证明复位后不会读取旧值。同步器的保护属性不能作为普通优化开销删除。onehot 与 binary 的 FF/译码代价不同，需逐模块对照，而不是全工程统一改成某一种编码。

### 工具选项与时序

现有构建脚本已经启用 resource_sharing=1、retiming=1、enable_dsrm=1；布局布线为 place2/route0/maxfan23。当前实际综合 .prj 的 ram_rw_check=0，不能把关闭它再次列为新收益，更不能在有读写冲突语义要求时任意删除旁路逻辑。

布局策略可做同源码对照，但只计完整布通且 setup/hold 均通过的结果。保持真实 50 MHz 和现有 CDC 边界；降低时钟约束或扩大 false_path 不能代替满足当前性能要求的资源优化。GSR 显式例化是否需要，应按所用原语和网表仿真流程确认；它本身不是已证明能回收 CLS 的方法。

## 4. 建议的实验顺序

1. **先试 HC-05 控制路径。** 原始最差路径经过 `requested_note -> note_map -> reply`，终点为 `reply_97_s1`，setup slack 仅 0.018 ns。可在命令接受、参数换算、配置写回和回复准备之间划分寄存边界；研究共享译码和低速串行计算，以减少重复比较和宽选择。UART 为 9600 baud，但必须保留同拍实体按键优先级、拒绝条件和命令原子性。流水化主要改善时序，面积收益需要实测，不能预先承诺。

2. **研究显示读口能否减少 RAM 副本。** `hub75e_rhythm_display.v` 有 1 份 head_memory，加 6 份 panel_memories 镜像，均为 64×7；它们提供不同地址的并行读取，不能只按总比特数直接合成一个普通双口 RAM。只有证明预取/时分读取可满足扫描、同址转发、滚动和密集音符输入后，才能减少副本。这个方向首先可能回收 BSRAM，调度新增的 CLS 也必须计入；释放出的 RAM 才可用于迁移其他合适的寄存器存储。

3. **逐模块检查控制装箱和局部运算复用。** 优先检查 keymap、download、take/store 的宽选择器和有效位屏蔽的中间寄存器。对互斥运算比较共享 ALU 与分立 ALU 的完整选择/控制成本。现有 APDS 串行均值复用已经进入当前源码，上一轮 95 CLS 收益不能再加一次。

4. **最后考虑音频数据通路的结构调整。** 现有验收报告的触摸最坏耗时为 1012/1024 拍；传感器和效果器目前可并行运行。不能将它们简单串在同一个运算器后，或用 50 MHz/采样率得出的 1024 拍当作全部空闲周期。需要先建立最坏周期预算，再改排程并做逐样本回归。

旧 Flash 头部旋转实验曾出现局部综合节省、整机 Logic 增加和未布通，因此不能直接搬入生产。详见 `../local_reuse_20261025/design_notes.md` 和 `../local_reuse_place1_20261025/README.md`；后者的历史 APDS 成功结果也不代表当前还能再次回收同样资源。

## 5. 收益目标与验收口径

若将 CLS 降到 95% 或以下，需从当前 11470 降到 10944，即净回收至少 526 CLS；降到 90% 或以下需净回收至少 1102 CLS。这是目标算术，不是当前可实现收益预测。

每次实验从同一冻结源码、器件、工具和构建设置出发，只改变一个主要因素；保存源码及工具哈希、综合层级、完整 PNR、未布通网络和 setup/hold 结果。必要功能测试围绕实际改变的协议竞争、原子快照、RAM 冲突、显示扫描和音频期限执行。失败候选不计为收益，不把不同候选的独立差值直接相加。

本轮完成的是资料调研、源码核对、资源热点排序和实验设计。没有新候选的综合/PNR 数字，也没有宣称达到 500 CLS 回收目标。
