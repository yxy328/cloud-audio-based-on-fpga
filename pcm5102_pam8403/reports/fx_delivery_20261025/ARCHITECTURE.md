# 本轮数据流、预留及协议边界

本文件是设计与实验记录，不表示三效果已接入生产。最小原型位于 `fx_sync/`、`fx_apds/`，不能烧作最终交付。

## 1. 当前与后续预留

当前源码核对：C 的 PITCH/VIB/EFFECT2 与 B1 已实现，不重复预留。D 未实现：`score[0:255]` 仍29位，没有逐事件弯音字段。B2 未实现：`note_map` 仍56位、指引7路。E 未实现的 producer 分裂、分源参数与三轨增益仍需额度；共享 `control_timbre/control_vibrato` 不是分源交付。

按较新的效果器规划，保留 D=150 Logic/30 CLS、B2=900/200、E=600/100、安全垫35 CLS，共 **1650 Logic/365 CLS/4 BSRAM**。这是本轮采用的最低预留口径。更早的侧边栏文档对完整 E 全覆盖估计280 CLS；若要求该口径，CLS 缺口再增加180，不能把 E100 说成 E 全覆盖已验证预算。Register/DSP 尚无足够分阶段估值，记录实际余量，不擅自将未估值记为已验证零成本。

## 2. 显示访问与配对实验

原扫描：ROW_PREP 1拍、64列×(PIXEL_PREP+SHIFT) 128拍、BLANK/SELECT/LATCH_HIGH/LATCH_LOW 各1拍，总133拍。LATCH_LOW 预取下一扫描行；每拍地址也预测 scroll 后的 head_top。插入经过距离/商流水，读旧字、碰撞前递、再 OR 提交。head_valid 优先清滚出行，然后允许同拍有效写重新置位。

原存储为一份插入读改写 RAM 与六份显示读 RAM。显示读地址分别为 `(head_top + scan_row - dy) mod64` 与其加32，dy=0,1,2；因此上下半屏总是可以组成同一个 `(a mod32)` 的14位配对字。候选保留一个插入 RAM、三个配对显示 RAM。修改的是存储字布局，没有增加扫描周期。

配对读改写必须保留未写的另一半，碰撞比较用低5位、有效位比较仍用完整6位；跨半屏同字碰撞也前递整个14位字。原参考断言与行掩码模型不变，既有测试只调整最后一段物理 RAM 预装载。另以本轮冻结的原 RTL 作未改动参考，逐拍比较逻辑行、行快照、所有外部输出及页状态。

功能通过不能代替面积/时序门槛：单独配对候选少3块BSRAM，但整机 Logic +775、CLS +159、7个setup违例，拒绝接入。层级XML显示显示模块自身 LUT/ALU -89，而 Flash/命令/曲谱等未改源码模块映射变大；不能将局部 -89 当成整机收益。组合候选单独重测，禁止与APDS收益直接相加。

## 3. 最小原型逐帧方程

令 x[n] 为现有 `u_output_mix` 输出，S 为16位饱和，w=0..8，湿增益 w/16。原型共用一个湿度，仅用于成本下探；最终三块独立湿度尚未实现。

- 合唱：C[n]=x[n] 写2048×16环形历史，每帧写一次。LFO每接受帧增1，周期65536帧，Fs=48828.125 Hz，频率0.7450580597 Hz。d=1024+7位整数三角波，范围1024..1151样本。c[n]=S(x[n]+(w*C[n-d]>>4))；旁路为x[n]。本轮为整数阶梯读取，没有分数延迟插值，未宣称实测平滑音分。
- 延迟：输入是 c[n]，独立4096×16历史。四档写入间隔1/2/4/6帧，长档仅湿声先一阶低通后降采样；完整速率干声始终保留。捕获时 h[k]=S((filtered_c>>1)+(h[k-4096]>>1))，其余帧湿抽头保持。d[n]=S(c[n]+(w*tap[n]>>4))；旁路为c[n]。原型反馈固定0.5，未实现最终四档反馈控件。
- 混响：输入是 d[n]，每两帧更新。半速输入为 `(d[n]+d[n-1])>>3`，包含平均与输入余量。4条comb长度618/658/707/751，写 `S(input+g*tap_i)`，并联输出为四个 `(tap_i>>2)` 之和。再串联308/244样本allpass：`v=S(u+(z>>1)); y=S(z-(v>>1)); memory=v`。原型g按0.625/0.75/0.8125/0.875的移位和计算。r[n]=S(d[n]+(w*allpass_out>>4))；不更新帧保持湿抽头，干声继续逐帧更新，旁路为d[n]。
- 输出 r[n] 进入原总音量，再到 I²S。三条写流分别是 x、合唱输出的延迟反馈流、混响各线反馈流，内容与采样率独立。

切换某块开关只清该块指针/有效样本计数/滤波状态；切延迟档只清延迟，切混响预设只清混响；全局reset/PANIC/perf_kill可清整链。关闭块的本地历史可能继续计算，但再次开启会按本地开关变化清尾，不继承关前尾音。

存储分配：合唱2048、延迟4096、混响4096，共10240×16。混响六分区起点0/618/1276/1983/2734/3042，总使用3286样本，未扩成16384。综合已确认效果器10块BSRAM（相对原4块新增6），一个MULTALU27X18，与原效果器DSP数量相同。

## 4. 完整访存调度

含接收沿最长37拍：IDLE接收；C_READ同步读与写、C_LOAD、C_MUL、C_MIX；D_START、D_READ、D_LOAD、D_MUL、D_MIX；R_START；六次(R_READ、R_LOAD、R_CALC、R_WRITE)；R_MUL、R_MIX输出。混响每次更新6读6写，读延迟和两级allpass串联都包含在24拍内。三个乘法状态复用同一乘法表达式和积寄存器。原型不是共享触摸/弯音处理器。

首次版本把混响RAM直接接到多用途tap寄存器，综合退成1024个额外SSRAM、Logic30790，已弃用。`fx_sync` 增加专用同步读输出，再送共享tap；独立模型样本不变，期限29→37拍，BSRAM正确推断为10块。错误推断版本不计成本或容量收益。

采样模型以队列历史和逐帧方程建立，不模拟RTL状态机/地址时序。259200帧逐样本相同，包括8种开关组合、四档延迟/混响、湿度钳位、复位、改预设和满幅定向饱和。该模型证据不表示原型与旧互斥效果逐样本兼容，也不表示最终App、录制或实物通过。

## 5. 兼容协议提案（未实施）

保留现有命令ID与回复kind0..29。四数字扩展可用：`EFFECT,3,mask,settings,mix`。首字段3是新格式标志；旧两字段只接受0/1/2，避免把旧1当作bit0合唱。

| 语法 | 语义 |
|---|---|
| `EFFECT,0,w` | 旧全旁路；mask=0 |
| `EFFECT,1,w` | 旧延迟；mask=2，反馈恢复旧0.5 |
| `EFFECT,2,w` | 旧合唱；mask=1，使用明确登记的旧深度配置 |
| `EFFECT,3,m,s,w` | 新四字段；m=0..7；s打包预设；w打包三块湿度 |
| `EFFECT,?` | 新App真实状态查询，回复kind30 |
| `EFFECT2,t` / `EFFECT2,?` | 保留旧延迟档位写入/查询；不占新命令ID |

settings位1..0=合唱深度、3..2=延迟档、5..4=反馈档、7..6=混响预设，15..8必须0。mix位3..0/7..4/11..8分别为C/D/R湿度，各0..8，15..12必须0。各深度/反馈码的最终表及原型成本未验证，不能现在生成固件。回复可用 `EFFECT3,#,##,###\r\n`（18字符）承载1位掩码、2位设置、3位湿度十六进制，短于32字符。kind31保留给B2 MAP分页。

旧CTRL2格式不改，可按“延迟优先、否则合唱、否则0”投影；仅混响投影0，旧App无法表达它。新App必须用EFFECT3完整状态，草稿和确认值分开。此提案未占用ROM，没有手改生成物。

## 6. TAKE 位域提案（未实施）

本轮按 `top.v:perf_live_state` 重新展开：527..512 gates；511..501空11位；500bank/499vibrato/498..496timbre；495..486空10位；485..484旧mode；483..480旧wet；479..477空3位；476..464master；463..448pitch；447..432gain；431..418空14位；417..288 sensor ADSR；287..224 touch ADSR；223..0 七路增量。合计528位，当前未改布局。

未来可用511作版本标志；版本1放486..484的mask、494..487的8位settings、431..420的12位mix；483..480保留兼容投影湿度。版本0必须按旧0/1/2枚举解码，不能直接当掩码。旧TAKE没有保存echo_tap，无法从旧文件恢复当时长延迟档；其兼容策略需明示继承旧行为（取回放时设备档位）或显式选择默认，不能宣称无损恢复缺失字段。新记录应保存全部设置及三块湿度，仍用528位同拍原子快照，不从live_state串行取值。

## 7. 原型尚未覆盖的交付要求

独立湿度/深度/反馈控制及成本、分数延迟插值/步进噪声评价、总网络RTL脉冲响应与可解释的RT60、定点尾音噪声底、旧协议与TAKE兼容、PANIC/回放端到端、三卡App及APK、最终全负载同帧压力/滑杆与回放联合验收、板上烧录与模拟音频对录均不是已完成项。原型移位和对负数逐项舍入，会出现定点尾音偏置，必须先定增益/舍入策略再声称音质和RT60达标。
