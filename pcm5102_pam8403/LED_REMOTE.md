# 手机切页、显示状态与实时预览（App v1.10）

本版落实 LED 联动的后两步：手机直接选择显示页、读回实际显示状态，以及在手机显示 FPGA 回传的频谱和三组音源幅度。

## 配套文件与使用

- Android 安装包：[FPGA-Score-led-remote.apk](android_app/dist/FPGA-Score-led-remote.apk)，v1.10 / versionCode 11，Android 10+，签名与旧版一致。
- FPGA 位流：[PCM5102_LED_REMOTE.fs](impl/pnr/PCM5102_LED_REMOTE.fs)，UserCode `0x00000147`；器件 GW5A-LV25MG121NC1/I0，顶层 `top`。此链接指向本地构建产物，源码仓库不保存 `impl/` 输出。
- 本次已生成配套位流，没有自动烧录开发板。手机与实体面板仍待联合验收，产物指纹和测试范围见 [验证记录](VERIFICATION.md)。

旧固件只有 `XY` 参数命令，不能支持新增切页或预览查询；使用新功能需要更新本页配套 FPGA 位流和 App。当前独立位流使用主工程 `top`，保留原数字音频上行通路；板上事件录制/Flash 回放属于另一开发目标 `top_take`，不要用本位流验收 TAKE 功能。旧安装包和旧主工程位流保留。

交付来自 `sim/build/led_remote_delivery/` 冻结源码，快照明确设置 `ENABLE_EVENT_TAKE=0`、`ENABLE_USB_AUDIO_RECORD=1`。共享工作区仍有其他开发修改；复现本页位流请使用 [LED_REMOTE_v1.10_sources.zip](sim/build/LED_REMOTE_v1.10_sources.zip)，不要用之后变动的源码替代已验证快照。源码包含 217 个文件及两份清单，解压后先阅读 `DELIVERY.md`；Android 构建脚本支持传入外部 SDK 和签名文件，不打包 SDK 或私钥。

1. 将上述配套位流以 SRAM Program 方式下载到开发板，手机安装 v1.10；SRAM 配置掉电丢失。
2. 系统配对 HC-05，在 App 中连接，找到“LED 显示控制与实时预览”卡片。
3. 点击“总览/曲谱、波形、XY 轨迹、频谱”直接切页。总览/曲谱共用自动页：空闲显示总览，播放时显示指引。
4. 点击“读取设备显示状态”，可看到请求页、已锁存的实际页、XY 请求参数和已经发布到显示缓存的参数。切换在完整 PWM 帧边界生效；XY 新曲线还需要完成下一段采集。
5. 点击“开启实时预览”，手机显示 FPGA 的 16 段频谱和触摸、红外/手势、吉他三组幅度。它们与 LED 使用相同的帧锁存值，手机不使用麦克风，也不重新计算 FFT。
6. 点击“停止预览”结束查询。切到后台或断开蓝牙也会停止；重新连接后需手动开启。

板上 S2 仍可切页和选图；开启预览时，手机会随之后的查询更新实际页和 XY 参数。预设参数按钮仍只设置 XY，不自动切到 XY 页面，可先点击“XY 轨迹”。

## 切页规则与带宽

手机切页不重启曲谱、不停止声音；隐藏曲谱继续推进。手机命令和 S2 同周期操作时，手机切页优先；若 S2 正被按住，会抑制该次按住剩余动作，避免松开时意外重启曲谱。后续新的 S2 按键操作照常生效。

预览采用请求/回复模式，没有后台连续推流。每次回复结束后至少等待 200ms 再查询，最多约 5 次/秒，9600bps 下通常约 4 次/秒；蓝牙实际延迟会影响更新速度。下载、事件日志录制、板上录制状态轮询或其他命令执行期间跳过查询，不积压预览任务。

每条 `VIZ?` 请求含 CRLF 共 6 字节；每条预览回复固定 32 字节。按每秒 5 次估算，上行 160 字节/秒、下行 30 字节/秒；9600bps / 8N1 单方向理论上限为 960 字节/秒。预览不传整屏像素或原始音频，不依赖新增高速模块。回复在 UART 上按完整行与事件日志仲裁，不插入半条日志。

断线、停止或切后台会清除预览图；超过 1.5 秒没有新数据时清除旧图并提示等待，不把旧数据继续显示为实时。预览数据不写入接收日志窗口，避免反复刷新长日志。

## 协议

ASCII，区分大小写，沿用 CR/LF/CRLF 收行和命令队列。

| 命令 | 回复 | 含义 |
| --- | --- | --- |
| `VIS,0` | `OK` | 请求总览/曲谱自动页 |
| `VIS,1` | `OK` | 请求波形页 |
| `VIS,2` | `OK` | 请求 XY 页 |
| `VIS,3` | `OK` | 请求频谱页 |
| `VIS?` | `VIS,m,a,r,p,s,t,f` | 请求模式、实际模式、请求 XY 比例/相位、已发布 XY 比例/相位、有效标志 |
| `VIZ?` | `V,` 加 28 个大写十六进制字符 | 一次原子快照；含 CRLF 共 32 字节 |

`m/a/r/p/s/t` 均为单字符 0～3。比例 0 为实际混音，1/2/3 为 1:1 / 1:2 / 2:3；相位 0/1/2/3 为 0° / 45° / 90° / 135°。标志 `f` 为单个十六进制字符，bit2=自动页当前使用状态总览，bit1=XY 缓存有效，bit0=FFT 结果有效。`OK` 表示切页请求已接受，实际显示以查询结果为准。

`VIZ?` 的 112 位载荷按高位在前编码，布局为：

| 位 | 数据 |
| --- | --- |
| 111:108 | 协议版本，固定 1 |
| 107:104 | 保留位 0 和上述三个有效标志 |
| 103:102 | 实际显示模式 |
| 101:100 / 99:98 | 已发布的 XY 比例 / 相位 |
| 97:92 / 91:86 / 85:80 | 触摸 / 红外手势 / 吉他幅度，0～56 |
| 79:0 | 16 段频谱，每段 5 位；第 i 段位于 `[5*i+4:5*i]`，0～31 |

各频段含义、约 0～3.05kHz 的显示范围及相对幅度刻度沿用 [音频可视化](AUDIO_VISUAL.md)。预览是声音反馈，不是校准声压或精密频谱测量。App 拒绝未知版本、保留标志、非法长度/字符和越界幅度。

RTL 在执行查询的一拍，把整份帧快照装入已有回复寄存器，之后逐字符发送；即使其间 LED 更新，回复也不会混入新帧。十六进制编码器分时复用，不新增 FFT、整屏缓存或采样时钟。
