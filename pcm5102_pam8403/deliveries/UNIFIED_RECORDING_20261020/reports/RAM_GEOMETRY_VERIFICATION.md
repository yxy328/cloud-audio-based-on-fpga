# RAM 几何优化与统一版验证

目标器件：GW5A-LV25MG121NC1/I0，主时钟 50 MHz；综合工具 Gowin V1.9.11.03 Education。

## 最终结果

**统一位流已完成。** `sim/build/unified/shared_p2r0/` 全部布通，生成 `PCM5102_UNIFIED.fs`。最终实际占用：Logic **22210/23040**、CLS **11381/11520**、BSRAM **46/56**、DSP **26.5/28**、寄存器 **10691/23280**。

50 MHz（20 ns）约束下 Fmax **50.717 MHz**，最差 Setup 裕量 **0.283 ns**，Setup/Hold 违例端点均为 **0**。ADC 的 2.5 MHz 派生时钟被正确识别。成功设置为布局算法 2、布线算法 0、最大扇出 23，已写入默认构建脚本。

当前 88 项 RTL、ROM、约束及工程文件与冻结综合输入的 SHA256 全部一致。最终整机仿真和 Java WAV 接收集成也已通过。尚未烧录开发板或安装手机进行真机验证。

## RAM 与逻辑

| 单模块综合对象 | 优化前 BSRAM | 优化后 BSRAM |
|---|---:|---:|
| 32 声部 `tdm_synth`（上下文、64 深度命令 FIFO、正弦 ROM） | 15 | 7 |
| 七声部独立变调 `voice_pitch_scaler` | 2 | 1 |

使用同一器件、同一综合设置单独测量。TDM 的实际传感器集成启用 `PRESET_FRAMES=1`；通用接口默认仍保留可任意设置的 `event_frames`。

- 每个 556 位声部上下文改为 16 个 36 位字，32 声部共 512×36，一块 BSRAM。预取下一声部与当前声部计算重叠，计算过程中分时写回已稳定的字段，无额外整声部写回缓冲。
- FIFO 保留 64 条容量及每时钟一条命令的突发接收能力。传感器生产者的时长只由音色决定，因此仅在该集成路径去除每条 17 位重复时长；FIFO 读取时根据排队时的音色重建。
- 正弦 ROM 的 256 个整数逐个与原 `sine_lookup.v` 常量一致，`python tools/generate_tdm_sine.py --check` 可复查。
- 变调的目标值使用小型分布式 RAM，当前值使用一块 BSRAM，保留原状态机时序。合并双口 BSRAM 时，工具推导了 GW5A-25 不支持的 read-before-write 模式，因此先采用寄存器目标库，再改为分布式 RAM，避免双口 BSRAM 同地址读写。

首轮 RAM 优化统一综合快照：`sim/build/unified/register_target_bend_syn/`。
实际 25K 综合：Logic **22819 / 23040**（LUT 19444、ALU 3375），寄存器 **11640 / 23280**，BSRAM **32 / 56**。

这轮实际 PnR 占用 Logic **22967 / 23040**、CLS **11520 / 11520**、BSRAM **39 / 56**，最终有 **488 条网络未布通**。未生成可用位流。这也证明不能只用综合的 Logic/BSRAM 余量判定整机一定放得下。

## 将已释放的 RAM 用于 LED 位图

曲谱位图由 448 位并行移位寄存器改为循环行地址，64 个有效位负责丢弃移出屏幕的行。插入使用一个 RAM 读改写端口，六个 RAM 副本并行供应上下半屏各三个相邻行，保持原来每时钟接收一条事件及 133 时钟行扫描。相同地址连续合并有显式转发，物理 RAM 读写同址时禁止读端口访问。

这里用七块剩余 BSRAM 换取逻辑和布线空间；复制的原因是并行读取带宽。`tb_hub75e_ram_equivalence` 与旧显示模块逐时钟比较全部引脚及完整 64 行位图，共 179908 次，包含连续滚动、128 时钟事件突发、OR 合并、停止和复位竞争。原 RGB5/PWM/位图算术回归与音频可视化四模式回归也已通过。

`ring_display_unified_syn` 综合降至 **22251 Logic**，减少 568；默认 PnR 为 **22405 Logic、11461 CLS、46 BSRAM**，仍有 371 条网络未布通。算法尝试分别放在 `ring_p1r1`、`ring_p2r2`、`ring_p3r1` 独立目录，输入源码哈希保持相同，主时钟仍为 20 ns。

三组未布通网络分别为 5323、172、5532。继续优化了传感器四条暂存队列：同一时钟接受的红外和手势事件共享一份原子 ADSR/音色快照，每个事件保存自己的音高和快照编号。四条事件容量、双写入顺序、逐时钟出队及满队列行为保持不变。

四槽快照池不会提前覆盖：每次分配至少对应一条事件，队列最多四条；当写指针绕回仍在使用的最旧快照时，接收新批次必然伴随最旧事件在同一边沿出队，其数据已在写入前被消费。`tb_sensor_queue_equivalence` 完成 249980 次逐时钟及 PCM 对照、7093 次出队、20 次双写入（覆盖全部写指针位置）和 1772 次快照池回绕，包含满队列、复位及测试命令竞争。

快照池及小型变调目标表使用分布式 RAM。`shared_snapshot_dsrm_syn` 综合为 **22132 Logic**（含 42 个 RAM16），但启用该映射后输入同步级也被工具改写，因此新增明确保留触发器的属性，使用 `shared_snapshot_sync_syn` 继续验证。主时钟与同步器时序例外的范围保持原样。

整机集成在循环 RAM 改写后再次通过：事件录制/重放/Flash 提交、忙状态恢复，492 个 PCM 采样与外部 I2S/HC-05 完全一致，下载期间 1184 个音频帧及 HUB75 持续运行。Java 接收器对这批实际仿真数据完成 ACK 顺序检查及 492 个 WAV 采样逐个比对。

## 等价与吞吐

- `tb_tdm_geometry_equivalence`：通用时长及预设时长两种配置各 800 个真实 1024 时钟采样帧，每种比较 25632 份完整 556 位上下文及输出 PCM。覆盖 32 声部、64 条满 FIFO、连续命令、八种音色、运行时 ADSR、颤音、和弦与测试命令；最忙 **950 时钟**，未超过 1024。
- `tb_bend_ram_equivalence`：与原始双 RAM 参考模块逐时钟比较 180000 次，含随机写入、非法索引、复位和采样边界竞争。寄存器候选及最终分布式目标库均通过；后者单独综合为 Register 290、LUT 271、ALU 59、BSRAM 1、RAM16 4。
- `tb_tdm_harmonic_equivalence`：500 个真实采样帧与旧算术实现逐采样一致。新旧流水线内部发布周期不同，因此在 I2S 消费的帧边界比较，不要求内部 `busy` 逐时钟相同。
- 原有 TDM 队列、ADSR、八音色、传感器音频与独立变调回归也必须通过。
- `tb_top_unified` 进一步验证事件录制、板上重放、Flash 提交、忙状态拒绝及恢复、外部 I2S 与 HC-05 PCM 一致、下载期间音频和 HUB75 持续运行。

32 声部的确定性周期上限（从采样启动边沿之后计）：LFO 4 + 最多 32 次分配×13 + 事件阶段退出 1 + 首声部预取 16 + 32 声部×16 + 发布 1 = **950 时钟**。每次分配包含至多 2 周期命令提取、1 周期请求、9 周期局部 RAM 修改及 1 周期提交；和弦/测试命令共用已提取命令，不会增加这个上限。首声部之后的 RAM 预取与计算完全重叠。包括启动边沿也只需 951，仍低于 1024。

## 构建复查

`tools/verify_ram_geometry.ps1` 重跑两种时长配置的完整上下文等价、变调逐时钟等价及相关回归；`tools/run_sim.ps1 -Tests tb_top_unified` 运行整机集成验证。

`tools/check_unified_build.ps1 -Label <新名称> -SynthesisOnly` 创建独立输入快照并只综合；快照中的 `sources.json` 记录 SHA256。

只有完成上述等价验证及资源核对后，才用 `tools/resume_unified_pnr.ps1 -Label <名称>` 对相同输入继续布局布线。脚本首先检查冻结输入哈希，禁止把后续修改混入已综合的网表。
