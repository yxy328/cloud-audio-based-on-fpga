# 侧边栏与演奏参数化方案审查

2026-10-21。依据当前提示词包、Android 源码、命令 / 回复生成器与 `hc05_keymap.v` 核对。
本次实施范围是阶段 A；后续阶段的资源数字是文档预算复核，不是本次重新综合的结果。

## 审查结论

阶段 A 可以独立实施：仅重组 App 界面、区分草稿与确认值、撤下已停用的 PCM 通路。
无需改 RTL、命令字典、回复模板、曲谱格式或声部弯音数值语义。
后续阶段不能直接照当前预算连续执行，需先解决以下两项。

| 问题 | 核对结果 | 后续处理时点 |
| --- | --- | --- |
| CLS 预留不闭合 | C100 + D30 + B2 200 + E280 + 安全垫35 = 645，超过余量465共180 | C / B2 / E 的资源规划 |
| 方案一仍有缺口 | 即使 B2 节省120，仍需525 CLS，超过465共60；不能把方案一写成已满足预算 | 选择 B2 / E 取舍之前 |
| 命令号不足 | 生成器现有58条，59～63剩5个；C四个聚合族后仅剩1个，IRMAP与TIMBRE至少还需2个 | 阶段 C 定协议之前，统筹 C 与 E |
| DSP 尚未复测 | 本轮没有重新综合，不以旧 DSP 数字批准新乘法器 | 首次后续 RTL 改动之前 |

可在阶段 C 统一规划聚合子命令，或在后续获授权调整命令族；本次不修改协议，也不提前决定 B2 / E 的取舍。

后续阶段B1已核对旧PnR报告并完成新PnR：DSP均为26.5/28，余量1.5；CLS余量变为467。以上原始资源预算的问题仍存在，最新数字见 [CHROMATIC_KEYS.md](CHROMATIC_KEYS.md)。

## 阶段 A 的具体修正

1. “固定6个分组”与实际列举的①～⑦矛盾，按 **7 个界面分组**实施。界面分组与“音色 / 滑音 / 颤音 / 弯音 / 震音 / 音高 / 音量”七个能力族并非同一张表。
2. 记录区保留 **3 张有效通路卡片**：板上事件、手机本地音符、事件日志。已经关闭的板上 PCM 不作为第四张卡片继续暴露。
3. `TAKE_REC` 固件检查 HOLD 不是2、POLY=16；日志 `REC_START` 另受8键、无延音、FSR用途等限制，且统一固件启用事件录制时会返回 `ERR,MISSING`。两个校验与说明分别呈现；日志增加 POLY=16 的前置校验。
4. `TONE` / `VIBRATO` / `BANK` / `ADSR` 没有当前参数查询，用本次连接收到的 `OK` 记录最后确认值；断线清除。不能杜撰状态查询。
5. 状态回读只更新确认值，保留未发送草稿。LED 实际页 / 图形在没有待发送改动时跟随设备；有改动时保留草稿，并同时标出设备实际选择。
6. Android 原生 `GradientDrawable.setStroke(width,color,dashWidth,dashGap)` 支持虚线，因此直接绘制2dp虚线；“外层粉色实心框＋内层底色”的叠图只会得到实线，无法满足原文视觉要求。
7. 原代码与 Manifest 已是 Code15 / 1.14-pedal，递增到 **Code16 / 1.15-sidebar**，两处同步。
8. 固定比率步进不能描述为上下1200音分都耗时21ms：按 `fsr_pitch_scaler.v` 的默认步进16，原音到上八度约20.97ms，到下八度约10.49ms。界面标明“原音上行1200音分约21ms”。
9. 红外 / 手势的“延音与复音”是界面分组中的不支持项，但 E 的七能力族地图没有给出对应实现。保留说明并列入 E 的资源审查，不把它写成 E0～E4 已能解锁。
