# 手机手动编辑 ADSR

2026-10-16：已实现触摸、红外/手势两套独立的运行时 ADSR。
主工程、LED 引脚和原演奏控制不变。App 编辑参数，FPGA 自行逐采样计算包络和声音。

## 使用

1. 安装本目录 `android_app/dist/FPGA-Score-debug.apk`，连接 HC-05。
2. 在“ADSR 包络编辑”选择“触摸七键”或“红外 / 手势 32 复音”。
3. 调四个滑块，或拖动曲线上的控制点：A 点调起音，D 点调衰减和保持音量，
   S 点单独调保持音量，R 点调释音。
4. 点击“应用 ADSR 到下一次发音”，收到 OK 后的新音符使用新参数。
   正在响的音符保留触发时的参数，松手后也按原 R 释音。
5. “恢复该音源原始包络”只恢复所选音源的后续音符。
   红外/手势恢复原五音色自带包络；触摸恢复顶层编译默认值。

曲线是**待发送草稿**，不表示已经读取 FPGA 当前状态。拖动/滑块不会自动发送命令。
恢复原始包络后草稿仍保留，可重新编辑；切换两个音源时分别保留各自的草稿。
蓝牙断开后 FPGA 保留当前参数继续演奏；FPGA 复位或断电后恢复默认，未增加 Flash 保存。

| 参数 | 范围 | 含义 |
| --- | --- | --- |
| A | 0～1000ms | 起始音量升至峰值的时间 |
| D | 0～1000ms | 峰值降至 S 的时间 |
| S | 0～100% | 保持阶段的音量比例，不是时长 |
| R | 0～1000ms | 松手/音符结束后，从当前音量降至零的时间 |

时间为0时使用最短一个音频采样，标称20.48μs。图中的保持段固定画300ms仅用于示意。
触摸按住保持，松手进入R；红外/手势沿用各音色触发时长，时间到就进入R。
如果A或A+D长于音符时长，会在起音/衰减途中从当前音量进入R。
预览显示音量包络；实际音频还叠加音色自身的衰减、压力增益和多声部混音。
ADSR 不控制物理弦吉他或旧 `ENABLE_DEMO_SCORE=1` 演示音轨；TEST32 保持专用的测试包络。App v1.3 的 `AUDITION` 复用七路触摸声部，因此使用触摸 ADSR 设置。
超过32个红外/手势声部时仍按最老声部替换，抢占会使用短淡出，因此被抢占音符的R可能提前结束。

## 蓝牙协议

默认9600 baud、8N1、大小写敏感，每条命令以CR/LF结束；等待完整回复后再发下一条。

```text
ADSR,TOUCH,10,80,60,200
ADSR,SENSOR,10,80,60,200
ADSR_RESET,TOUCH
ADSR_RESET,SENSOR
```

ADSR字段依次为 A毫秒、D毫秒、S百分比、R毫秒。成功回复 `OK\r\n`。
超范围回复 `ERR,RANGE`，缺字段/多字段/负号/非数字/未知音源回复 `ERR,CMD`；
失败不修改任何参数。允许演奏过程中配置，不会触发音符或改变改键/曲谱的忙保护。
调参命令需要串口传输时间，收到ACK再演奏；正常传感器触发仍走本地硬件通路。

## FPGA 实现

- `adsr_config.v` 用一套小型串行除法器转换两套配置并原子提交。
  按Fs=50MHz/1024，毫秒转采样为 `round(ms*3125/64)`，S按百分比换算。
- 触摸每声部在门控上升沿锁存参数；现有线性包络改为16位时长计数，
  保留逐采样精确端点、分数余量、提前松手及连续重触发。
- 红外/手势在事件进入队列时保存完整配置，再存入声部上下文；排队期间再次调参也不改旧事件。
  每个声部增加A/D/S/R状态、计数、相位及起始/目标音量。
- TDM利用查表期间原来空闲的乘法流水线计算包络，未增加每声部处理周期。
  触摸增益为16位；TDM音量为0～256，约0.39%一级，S按最接近的级别量化。
- TEST32事件不携带用户ADSR，频谱验证仍使用原来的稳定32路正弦测试。
- 为容纳新功能，蓝牙参数解析从512位移位缓存+动态选字节改为同步BRAM命令缓存，
  保留原有MAP、曲谱、日志与演奏控制协议。
