# 数字音频效果器：2026-10-24 前置核验

本轮只新增 testbench、审计工具和记录；未改生产 RTL、协议生成物、App 或默认位流。接手时已有去重 PnR 策略在其他进程中运行，本轮复用了这些隔离快照并核验输入、资源、布线和时序，没有启动重复构建。原提示词的完整效果器实现尚未开始。

结论：新基线数字属实，但原文的共享帧预算、①预计回收 350～450 CLS、合唱音分、资源缺口算式及部分协议限制不能直接作为实现依据。前置测量完成不等于路线 B 已满足资源与架构条件。

## 1. 同帧实测

复现：`./tools/run_sim.ps1 -Tests tb_fx_frame_budget`。

`sim/tb_fx_frame_budget.v` 保持 50 MHz、每帧 1024 拍；通过 UART 与 TTP229 模型引脚加载曲谱、设置四路持续弯音、切换 16 键和现有干声/延迟/合唱模式。UART 加速至 500 kbaud，启动等待为 100 µs，ADSR 使用短测试参数。为跳过纯视觉预滚，在下载曲谱进入 RUN 后仅一次推进其 elapsed_ms 至 60；全部被计量的音频帧正常逐拍运行。FSR 关闭、全局比率为 unity；弯音扫描和四路 slew 仍真实运行。没有强制 RTL 信号。

| 项目 | 同帧最大占用，含接受输入的时钟沿 |
|---|---:|
| 触摸合成 | 1012 / 1024 |
| 七路弯音扫描 | 43 / 1024 |
| 现有效果器 | 5 / 1024 |
| 上述三者逐项相加，仅作诊断 | 1060 |
| 上述三者忙碌周期的并集 | 1012 |
| 至少两个引擎同时忙碌的周期 | 43 |
| 效果器自身空闲周期 | 1019 |
| 三者同时空闲周期 | 12 |

1411 个完整帧通过；其中 319 帧同时满足 16 键、至少四路 target≠current、曲谱播放及效果开启。8/16 模式切换造成的一次重新初始化窗口排除在完整帧统计外。覆盖 4 个同帧 16 声部包络除法的边界帧，每次 256 个 DIVIDE 周期。超限帧 0，RTL overrun 0，触摸/输出混音 clipped 周期 0。触摸、弯音、效果器完成延迟分别为 1012、43、5 拍。

触摸使用 `u_touch_synth.contexts`，弯音使用 `u_fsr_pitch_scaler.individual.u_bend` 的乘法器和 RAM，效果器使用 `u_effects.memory`；它们没有共用一个时分处理器或 RAM 端口。因此不能把 1012+43+5 当作串行预算；“总空闲只有 12 拍，所以混响不能开工”同样不成立。混响应验证自身 FSM 的读写、依赖、输入/输出帧契约及 1024 拍 deadline。当前测试没有实现或验证新混响，也没有验证尚未实现的 12 路弯音。

逐帧 CSV 和 PASS 原文保存在 `reports/fx_preflight_20261024/`。

## 3. 提示词仍需纠正的内容

1. **缺口算式。** 按提示词自身估算，本包 210～380，加 D/B2/E/安全垫 365，减基线余量 220，所需额外回收是 **355～525 CLS**，不是 370～540。假设①能回收 350，最坏差 175，不是 190；但实测已经推翻①这项供给假设。②③也没有实测，不能承诺足以覆盖。
2. **合唱音分。** 周期 65536 个接受采样、0.7450580597 Hz 和 6 位峰峰 63 采样/1.29024 ms 正确。5.22 音分来自正弦 LFO 的最大斜率公式；RTL 是整数阶梯三角波。上行每 512 帧延迟跳一个采样，若把阶梯近似成连续斜坡，非端点区斜率约 1/512，音高偏移约 −3.385/+3.378 音分，并伴随实际整数读地址跳变。它不是已证实的“5.22 音分平滑合唱”。原文小量式还漏了 2π：正弦情况下系数应为约 10878，而不是 1731.2。依据是 Julius O. Smith 的[时变延迟频率推导](https://www.dsprelated.com/freebooks/pasp/Time_Varying_Delay_Line_Reads.html)。
3. **路线 B 内存与顺序矛盾。** §0/§3.5/界面要求“合唱→延迟→混响”，§路线 B 却把共用写流限定成“延迟→合唱”。一个历史写流不能一般性地同时保存独立合唱输入历史和串联延迟输入历史；尤其长延迟按 2/4/6 降采样写入时，直接复用它也不能维持全速率 20.97 ms 合唱。必须先给出明确环形区、写入数据流、更新速率及串联方程；8192 总容量不能自动证明三块正确串联。
4. **解析器已经支持四字段。** `parse_numbers` 有 `value0/value1/value2` 加末字段 `accumulator`。PITCH/VIB/ADSR 已调用四字段版本；本轮 testbench 的 `PITCH,,,256` 也实际通过。“最多三字段、第四字段必须先扩解析器”不成立。新 EFFECT handler 仍需自行增加字段校验和回归。
5. **回复槽可以各分一个。** kind 30/31 两个空位足以分配给 EFFECT3 回复和 B2 MAP 分页，属于登记问题，不是两边不能同时实现。规划为 30=EFFECT3、31=B2 MAP 分页；现有 0～29 保留。命令表当前只匹配 `EFFECT,`，没有 `EFFECT3?`；应复用 `EFFECT,?` 等现有前缀查询，并以 EFFECT3 作为回复名，避免和“禁止新增命令号”自相矛盾。本轮仅登记方案，未生成或占用 ROM。
6. **RAM16 口径。** 新基线是 44 个 SSRAM(RAM16)，不是 40；报告的 Logic 为 `21699 + 6×44 = 21963`，不能按“44 个 RAM16≈22 CLS”直接换算。理论 Logic 等价值也不是可交付回收量；换存储后要看完整 PnR。
7. **RT60 表只有最短 comb 的数。** 618 采样 comb 的理想值为 0.372/0.608/0.842/1.309 s；751 采样 comb 在相同 g 下是 0.452/0.739/1.023/1.591 s。不能把最短线的表直接当作整个 4 comb+2 allpass 网络的实测 RT60；仍须测总脉冲响应。
8. **保持正确的项。** 5 个状态需要 5 拍、约 20 个状态需要至少 5 位编码、BSRAM 47=26+12+9、基线余量、7→12 路扫描推导 43→73 及 4 comb+2 allpass 共 **12 次读写**均正确。但移位加的加法器与选路仍有逻辑成本，不能称为资源免费；Logic/2 只是理想下界，不能承诺打包一定取得该下界。[GW5A 官方数据手册](https://cdn.gowinsemi.com.cn/DS1103E.pdf)确认每 CLS 含两个 LUT 和两个寄存器。
