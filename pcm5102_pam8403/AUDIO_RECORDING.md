# 备用方案：现场演奏音频录制与高速回传

2026-10-20 新增独立 [HC-05路线2：Flash离线PCM与慢速WAV回传](HC05_AUDIO_ROUTE2.md)，使用现有9600bps，当前待实板验收。下文USB方案仍为备用，旧协议、吞吐、资源与新目标应分别查看。

**2026-10-19 决定：暂不启用此方案，保留代码作为备用。当前手机与FPGA只通过HC-05通信，不需要USB串口模块、RTS接线或手机OTG。App v1.11不创建USB接收器，也不开放USB录音入口。**

当前HC-05负责曲谱、演奏参数、LED控制/低速预览和相应固件支持的事件/状态通信。保持现有9600bps设置，不将完整PCM音频改走该通道。板上事件录制回放是另一个目标，进度见[RECORD_PLAYBACK.md](RECORD_PLAYBACK.md)，不能据此宣称已完成音频WAV回传。

下文保留备用方案的协议、接线及历史数字验证，只有以后明确启用高速通道时才适用。

FPGA 默认参数现为 `ENABLE_USB_AUDIO_RECORD=0`，综合时裁掉此硬件；`AREC?` 返回 `AREC,0,0,0`，`AREC_START` 返回 `ERR,STATE`。本轮 [资源优化位流](HC05_RESOURCE_OPTIMIZATION.md)采用此配置。备用 RTL 测试显式设为 1；以后启用实板 USB 方案时，还须恢复仅针对 `legacy_pcm.u_audio_record/cts_meta*/D` 的 CTS 第一级同步器约束并重新构建、检查时序。

App v1.6 / Code7：单向数字音频录音链路已实现，RTL、手机文件接收测试及50MHz布局布线通过；USB模块、OTG与实板持续录音尚待验收。[构建与验证记录](VERIFICATION.md)列出当前产物。现有REC_START仍只表示事件日志。

## 数据来源与禁止预录PCM播放

触摸、红外、手势、吉他实时合成 → 混音 → 音效 → 总音量 → 最终audio_sample。
在与I²S锁存相同的frame_ce复制最终16位采样到录音FIFO，I²S输出继续正常运行。录音不插入声音处理级，不占用声部上下文RAM，不阻塞合成。静音、尾音、参数变化和16键演奏均按最终输出记录。

本功能只有采样、上行及手机文件保存，没有PCM下载或FPGA录音回放入口。数学正弦表、实时音效延迟线和现场生成的数字采样不构成预置整段录音。

## 时隙与吞吐

- 50MHz每1024个主时钟产生一个音频帧，Fs=48828.125Hz，周期20.48µs。
- 16路触摸与32路红外/手势分别在自己的合成器里时分复用运算；录音不逐声部发送，只复制一份最终单声道混音。
- 录音采用独立状态机安排FIFO写入、同步读取、逐位CRC与发送时隙；UART字节只在CTS允许时启动，已经开始的字节完整发送。
- 16位单声道载荷97656.25B/s。独立2Mbps、8N1 UART理论载荷200000B/s；每256样本增加18字节封装，持续数据约101.1kB/s，给流控留出余量。
- HC-05仍是9600bps控制/事件日志通道，不承载音频；按完整行仲裁事件日志与命令回复。

FIFO默认1024个采样，约20.97ms。CTS暂停过久导致FIFO满时，录音在首个丢样处中止，保留连续前缀，结束包明确标记不完整；声音继续运行。有限FIFO不能保证任意长的USB断连仍无损。

## 接线

根据矽速官方Tang Primer 25K Dock原理图第1页核对，新增两根空闲J3信号，其他外设不改线：

| 开发板 | USB转串口模块 |
| --- | --- |
| J3第27脚 / FPGA J7 / audio_rec_tx | RXD |
| J3第29脚 / FPGA L8 / audio_rec_cts_n | RTS（低有效，模块接收流控输出） |
| J3第12脚 GND | GND |

模块使用3.3V TTL，须支持真实2Mbps及RTS/CTS硬件流控，例如CP2102N；普通旧CP2102不能按型号相近推断可用。模块USB经OTG连接支持USB Host的安卓手机。FPGA、功放和LED按现有方式供电，不将模块5V/TX误接到FPGA输入。这里不使用底板USB-A手柄口，也不承诺板载调试器固件的UART高速吞吐。

audio_rec_cts_n带上拉，未连接时默认禁止发送；必须接好RTS。USB断开、速率或流控配置错误时，手机不能将录音标为完整。

## HC-05控制命令

| 命令 | 含义 |
| --- | --- |
| AREC_START,0..65535 | 指定手机本次会话号，开始复制后续音频帧；忙返回ERR,BUSY，CTS未就绪返回ERR,STATE |
| AREC_STOP | 停止采集，排空已捕获数据，再发送结束包；OK不是文件完成标记 |
| AREC_ABORT | 中止采集和传输，清空该次FIFO，不影响实时声音；手机文件标记不完整 |
| AREC? | 回复AREC,忙,CTS就绪,溢出标志 |

所有命令以CR/LF结束，成功回复OK。AREC与原事件日志REC_START/REC_STOP独立，录音期间可以改变音色、音效、音量、ADSR和门控，这些变化会体现在实际采样中。新会话必须等上次结束或先中止；手机只接受匹配会话号的数据。

## 高速上行二进制协议 FAR1

每包为16字节头、载荷、2字节CRC，所有数值按小端。CRC为CRC-16/CCITT-FALSE，初值0xFFFF、多项式0x1021、不反射、不异或输出，覆盖完整包头与载荷，CRC低字节先发。

| 偏移 | 字节 | 内容 |
| --- | --- | --- |
| 0 | 4 | ASCII FAR1 |
| 4 | 1 | 类型：1开始、2采样、3结束 |
| 5 | 1 | 标志bit0=录音FIFO溢出，其他位0 |
| 6 | 2 | 载荷字节数 |
| 8 | 2 | 包序号，从0开始，按16位自然回绕 |
| 10 | 2 | HC-05命令指定的会话号 |
| 12 | 4 | 本包首采样索引，结束包为总采样数 |

- 开始包：8字节载荷，u32主时钟频率、u16采样分频、u8位宽16、u8声道数1；序号与索引均0。
- 采样包：1～256个有符号16位小端采样，通常256个，停止时允许不足整包的尾部；无压缩、无降采样。
- 结束包：4字节丢样标记，正常为0，FIFO溢出中止为1。数据和结束包都参与序号、采样位置与CRC核对。

手机检测CRC错误、序号缺失、采样索引不连续、会话错误或结束包缺失时，不能标为完整。受损录音仅保留已验证的连续前缀，不把缺失时间压缩成看似完整的声音。

## 手机文件

手机边接收边写入内部缓存WAV，内存不会随时长线性增长。收到匹配结束包、确认无丢样且落盘成功后才允许显示完整。中止或断连的文件标为INCOMPLETE。

USB接收使用32个4096字节的排队请求和无超时的UsbRequest等待，使文件/CRC处理期间仍有USB缓冲，关闭端口会取消请求。不使用连续高速传输下容易丢字节的短超时bulkTransfer轮询；有限缓冲仍需与硬件RTS配合，不能替代实际吞吐验收。

1. 更新配套FPGA位流，安装[v1.6 APK](android_app/dist/FPGA-Score-debug.apk)，按上表接入2Mbps、3.3V且带RTS流控的USB串口模块。
2. 手机通过OTG连接模块；App连接HC-05后，在“08 完整演奏音频录制”选择USB串口并允许设备访问。
3. 点击“开始音频录制”，保持App前台；演奏触摸、红外、手势或吉他，可同时调节音色/音效/音量。
4. 点击“停止并等待完整录音”，等待收到结束包并显示“完整录音已保存”，再导出WAV。停止命令的OK只表示命令已收到。
5. 中止、USB断连、CRC/序号/采样位置错误、FIFO溢出、结束包超时均不能当作完整录音。可导出INCOMPLETE文件，内容只保留已验证的连续前缀。

HC-05断开本身不切断独立USB音频；先重连控制通道，再停止录制。每次新录制先发送AREC_ABORT清理上次状态。App关闭或系统终止不保证收到结束包；本版本不含后台录音服务，尚未开始的空文件不提供音频导出。

标准WAV的采样率字段为整数，本版本写入48828Hz；额外srAT RIFF块保存50000000/1024的精确采样率，PCM字保持原值，不做重采样。文件可通过系统文件选择器导出；没有FPGA回放功能。

本功能记录I²S之前的数字混音；不包含DAC、功放、扬声器或环境麦克风的模拟声音。当前I²S左右声道是同一采样的副本，因此以单声道保存，没有漏掉独立右声道。

## 数字验证与复现

- `tools/run_sim.ps1 -Tests tb_audio_record_stream,tb_hc05_audio_record,tb_top_audio_record`：2Mbps实际位时序、CTS暂停、CRC/序号/会话/索引、尾包、溢出连续前缀、中止及重启；21条HC-05命令事务；712个整机回传采样与外部I²S解码逐个一致。
- 整机包含触摸、真实IR引脚变化、分类后的手势事件注入、吉他、录制中音效/总音量变化，核对TDM期限和HUB75扫描；APDS光学分类不在这项数字测试范围内。
- `android_app/test-core.ps1`：有符号采样、分片/粘包、CRC损坏/丢包/溢出/缺END、序号回绕、随机数据、WAV头；读取上述两份UART仿真数据，逐字比较1501个模块采样和712个整机采样。
