# 手机逐声部实时变调

App 自 v1.2 起提供“七声部独立滑音”卡片，当前 v1.3 继续支持；七个滑杆分别对应 TTP229 OUT1～OUT7。
例如同时按住 OUT1/3/5 的 C/E/G，只拖动声部3，E 会连续升降，C/G 保持各自音高。
它改变正在响的音，也改变该键以后触发的音；松键不会清除设置。
这是七个固定触摸声部的控制，尚不支持寻址红外/手势动态分配的32个声部或单弦吉他。

## 使用

1. FPGA 下载配套位流，手机安装 [当前 APK](android_app/dist/FPGA-Score-debug.apk)（v1.3，支持本页功能）。
2. 配对并连接 HC-05。按住多个触摸键，拖动对应声部滑杆。
3. 范围为 **−1200～+1200音分（−12～+12半音，上下一个八度）**，步进1音分。
   标签同时显示编辑值和收到 OK 的设备目标值；确认目标不等于实际过渡已经完成。
4. “全部回正”使七声部变调回到0半音；FSR仍按其当前模式工作。
5. 断开时可编辑草稿，连接后点击“发送全部音高”才会应用这些草稿。
   重连不会查询设备当前变调，标签会显示“设备目标未确认”。

连接时每约100ms最多发一条最新滑杆位置，各键轮流处理，始终只保持一条待确认命令。
同一滑杆连续拖动会覆盖尚未发送的旧位置；收到旧位置确认不会丢掉后来的新位置。
下载/其他命令期间暂存最新拖动，任务结束后继续；断开/失败时丢弃待发任务，保留编辑值。
“发送全部”按点击时快照逐键确认，不具备七键原子提交；中途失败时部分键可能已经应用。

## FPGA 与协议

9600波特率、8N1、ASCII，CR/LF/CRLF终止，沿用逐行确认：

| 命令 | 行为 | 回复 |
| --- | --- | --- |
| `BEND,1,16384` | 第1声部回正，比例1.0 | `OK` |
| `BEND,3,17358` | 第3声部约升100音分 | `OK` |
| `BEND,7,8192` | 第7声部降一个八度 | `OK` |
| `BEND,7,32768` | 第7声部升一个八度 | `OK` |
| `BEND_RESET` | 七路目标全部回正，平滑返回 | `OK` |

`BEND,<key>,<ratio>` 要求键号1～7、无符号十进制比例8192～32768。
字段缺失/多余/负号/非法字符返回 `ERR,CMD`；键号和数值越界返回 `ERR,RANGE`。
无效命令不修改任何声部目标。与 MAP 不同，BEND 允许正在发声、曲谱运行和事件录制期间使用。
比例采用Q2.14：`ratio=round(16384*2^(音分/1200))`，全范围量化误差小于0.11音分。

音高按 `原MIDI频率 × FSR全局比例 × 本声部比例` 计算。
FSR音量模式下全局音高为1；滑音模式下仍同时作用于七路。
BEND不会改MAP、曲谱音符、门控、ADSR或相位累加器；因此变调过程中不重新起音。
触摸MIDI基础映射仍限定60～72；生产通路用26位基础增量（均小于2^26），
一个26×16乘法器先做FSR缩放，再做逐声部缩放，每帧最多43个50MHz时钟更新全部七路。
两个小块RAM保存七路目标与当前比例，七键MIDI查表也改用同步块ROM，以节省逻辑资源。
比例每音频帧最多改变16/16384，最远跨度0.5→2.0约30.72ms；回正→高八度约20.97ms。
DDS下一帧使用更新后的增量，相位连续，包络保持。触摸正弦查表与包络乘法间增加一个每时钟更新的寄存器；由于相位在音频帧间保持，帧采样结果与原实现逐样本一致，不增加音频帧延迟。ADSR的毫秒换算改用五次乘5的串行移位加法，仅多用若干控制时钟，数值等价。

蓝牙串行发送、App调度和该平滑时间不能算作≤5ms/≤10ms的实时演奏延迟证明。
本地触摸/红外音符触发仍走原硬件路径；现场延迟仍须传感器到DAC实测。

## 状态、验收与边界

- 目标保存在FPGA易失RAM，断开蓝牙后继续有效，复位/重新下载后归零。
- 现场先全部回正，按住三键；只拖动其中一键，观察/听取只有该谱峰移动，再回正。
  开启FSR滑音后，三个谱峰随压力共同移动，同时保留各自App偏移。
- 日志仍只记录触摸/压力事件，不记录BEND/ADSR/红外/手势/吉他设置，不能完整复现含这些控制的演奏。
- 新旧App/位流要配套更新；旧位流不识别BEND，App收到错误会关闭该蓝牙连接。
- 数字RTL仿真和软件测试见 `VERIFICATION.md`；当前未代替上板、手机拖动与模拟频谱验收。
