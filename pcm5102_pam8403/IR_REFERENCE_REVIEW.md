# 红外对管与 TDM 参考核对

2026-10-15。参考目录：`../fpga-musical-magic-box-master/1/fpga_project_1/`。
本轮读取当前源码、工程列表、fix13/fix16/fix17说明并运行红外输入单元测试；
没有把红外接入当前主工程，也没有修改主工程RTL、引脚或位流。

## 可复用的红外输入

当前 `src/ir_strings.v` 实现八路独立数字输入，不依赖 APDS-9960 或 OLED。

- 通光为低，遮挡为高；按参考电路记录，未遮挡约0V，遮挡约2.9V。
- 输入经过两级同步；每一路的两个电平边沿都需稳定50000个50MHz周期，约1ms。
- 复位时各路视为遮挡、尚未准备。必须先收到稳定通光低电平，才允许下一次遮挡触发。
- 每次遮挡只发一个事件；一直挡住不重发。移开达到滤波时间后才重新准备。
- 输入配置弱上拉，未连接通道保持高电平，不会在上电时自动发音。
- 同时遮挡的通道保存在8位待发掩码，按编号从小到大每系统时钟分发一个事件，
  同一批八路最多用8个分发时钟。它不是音符FIFO，同一路尚未分发的重复事件可能合并；
  默认双边1ms滤波下，一路重新触发所需时间远长于八路分发时间。

音高映射位于参考 `src/gesture_audio.v`：通道1～8对应
C4、D4、E4、F4、G4、A4、B4、C5，不受手势高低音组选择影响。
这是边沿触发、按音色时长自然结束的演奏方式；保持遮挡不会持续延音，
移开也不会立即截断已触发的尾音。

参考文档 `docs/ir_strings_fix13.md` 记录的接法是：独立3.3V稳压供电，
发射管串330Ω、接收管用100kΩ上拉，接收输出送FPGA数字输入，供电负端与FPGA共地。
该文档记录仅一对做过电压实测，不能当作当前实物或八路串扰已验证。
电路极性与实际器件应按原有接法及实测确认，不能把这两个电阻值视为所有型号的通用参数。

## TDM 引擎参考

参考生产工程 `gesture_tdm32.gprj` 启用 `src/tdm_synth.v`，旧并行
`poly_synth.v`/`poly_voice.v`没有加入其生产文件列表。

`tdm_synth.v`实际只有一处变量乘法 `mul_product <= mul_a * mul_b`，
操作数为33×18位。32份声部状态存入RAM，由状态机共享该乘法流水线及正弦查表；
这属于实际运算时分复用。参考说明记载该通路映射为一个MULT27X36、占两个物理DSP，
整套工程为9/28 DSP，额外DSP用于手势识别等其他模块。本轮未重新综合该参考工程，
9/28和Fmax52.172MHz取自其fix17验证文档，不能作为当前融合工程的结果。

其他可借鉴之处包括64项事件FIFO、每帧快照、每帧最多分配32音、
声部满时替换最早声部、32采样短淡出、饱和混音和帧截止违例诊断。
参考文档记录的最坏突发计算为871周期，50MHz/48828.125Hz下每帧预算1024周期。

## 接入主工程时的适配点

1. 复用红外同步/滤波/准备/分发逻辑，接入独立音符事件，不与TTP229的K8模式键混用。
2. 多路红外需要能保留连续事件的复音引擎。当前主工程手势音源是单声部重触发，
   直接把八个连续红外事件接进去会相互替换；应配合TDM事件/声部管理进行适配。
3. 参考 `gesture_audio.v` 同周期只选红外，手势事件会被让掉；主工程若要保留
   多输入同时演奏，应明确仲裁或分别缓存，不能把音频FIFO当作已经保留了上游所有事件。
4. 主工程TTP229按住维持、松开释放，以及FSR实时音量/音高接口需要保留。
   参考TDM当前是定时音符事件接口，不能直接替换现有触摸门控与压力路径。
5. 保留用户已确认的S1/S2曲谱控制、HC-05命令和安卓App操作；参考的实体按键分工不同。
6. 所有音源继续使用主工程frame_ce及单套PCM5102串行器；直接使用
   `tdm_synth`的PCM接口，不把参考顶层自己的I²S/复位/OLED/UART整套覆盖进来。
