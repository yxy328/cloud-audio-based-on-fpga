## 工程文件和数据路径

| 文件 | 用途 |
| --- | --- |
| `src/uart_8n1.v`（新增） | 9600/8N1 全双工 UART、128 字节队列与同步预取、错误帧/溢出恢复 |
| `src/hc05_keymap.v`（新增） | 文本命令解析、七键 MIDI 寄存器、忙碌保护和回复 |
| `src/midi_note_lut.v`（新增） | MIDI 60～72 转换为相位增量，查表输出经过寄存器 |
| `src/fsr_pitch_scaler.v`（修改） | 接收运行时基础增量；共用一条有流水级的压力缩放通路 |
| `src/top.v`（修改） | 接入上述模块；歌曲和触摸状态提供修改保护 |
| `.gprj`、`.cst`、`.sdc`（修改） | 加入文件、两根 HC-05 信号约束和第一级接收同步约束 |

```text
HC-05 → UART → 命令解析/七键 MIDI 寄存器
                            ↓
                   注册后的 MIDI 增量查表
                            ↓
                  注册选择 → 乘法 → 注册输出
                            ↓
                原 DDS → ADSR → 混音 → I²S
```

全部逻辑使用原 50MHz 时钟，UART 使用计数器，没有新增内部时钟。
共用压力缩放通路每个音频帧只启动一轮，随后最多43个时钟完成FSR与逐声部两次缩放，更新七个输出，其余时间保持静止。
它在帧脉冲后读取新压力比例，下一帧 DDS 采样前已完成全部更新，没有增加压力控制的音频帧延迟。
查表另占 1 个时钟；任意时刻改键后最多约 21µs 得到新基础音高，远小于按键约 1～2ms 的确认时间。
压力乘法与 DDS 累加器之间有寄存器；串口解析不串入音频采样运算。
`clk_div.v`、DDS、ADSR、混音、I²S 模块和采样分频保持现有实现。
SDC 仅新增 UART 第一级同步寄存器的异步输入例外，第二级和后续逻辑正常分析，未放宽内部时序。

## 接线与手机设置

断电接线；沿用之前独立 HC-05 工程的引脚：

| HC-05 | Tang Primer 25K Dock J3 |
| --- | --- |
| TXD | 第 **16** 脚 / FPGA **F2** / `hc05_rx` |
| RXD | 第 **15** 脚 / FPGA **F1** / `hc05_tx` |
| GND | 第 **12** 脚 / 共地 |
| VCC | 按模块版本供电；明确支持 5V 的带稳压底板可接第 **11** 脚 |

UART 信号为 3.3V TTL；裸核心板不能直接接 5V。
J3 15/16 脚不可同时接 SDRAM 扩展板或其他设备。
TTP229、PCM5102 和 FSR402 原接线继续使用，无需改动。

安卓手机使用支持经典蓝牙 SPP 的终端：系统配对后在 App 内连接 HC-05。
模块正常数据模式 UART 需为 **9600、8 数据位、无校验、1 停止位、无流控**；
正常上电不要按 AT 按钮。其他数据波特率需修改 `top.HC05_BAUD` 后重新编译。

关闭手机 App 本地回显，**发送结束符选 LF（换行）**；CR 或 CRLF 也支持。
没有结束符时 FPGA 继续等待，不会执行命令。所有回复以 CRLF 结束。
命令为大写 ASCII，不带空格。建议发送一条后等待对应回复，再发下一条。
本版本返回命令结果，不逐字回显收到的文本。

## 命令

| 手机发送（App 自动追加 LF） | FPGA 回复 | 行为 |
| --- | --- | --- |
| `PING` | `PONG` | 检查双向通信，演奏期间也可用 |
| `MAP?` | `MAP,60,62,64,65,67,69,71` | 依次列出当前第 1～7 键 MIDI 编号，演奏期间也可用 |
| `MAP,1,67` | `OK,MAP,1,67` | 第 1 键改为 G4 / Sol |
| `MAP_RESET` | `OK,MAP_RESET` | 恢复全部七键默认映射 |

`MAP,<键号>,<MIDI>` 的键号必须是单个数字 **1～7**，MIDI 必须是两位十进制 **60～72**（C4～C5）。
支持这个音域内的全部半音，允许多个键映射到同一音高。
K8 保留压力音量/音高模式切换。默认 `ENABLE_DEMO_SCORE=0`，音符曲谱推进七轨 HUB75E 屏幕指引，不能自动发声。单键按住时可由压力实时变调，复音时统一影响七键。

| 错误回复 | 原因 |
| --- | --- |
| `ERR,BUSY` | 启动校准未完成、歌曲在播放/释放尾音、音符键按住/释放尾音，或录制保护输入有效 |
| `ERR,KEY` | 键号不在 1～7 |
| `ERR,NOTE` | 音符不在 60～72 |
| `ERR,CMD` | 未知命令、大小写/格式/字符不正确 |
| `ERR,LENGTH` | 一行超过 64 个字符；整行丢弃，等待结束符后回复 |
| `ERR,UART` | 停止位错误或接收队列溢出；丢弃待处理输入及当前损坏行，到结束符后恢复 |

所有被拒绝的命令均保持原映射。修改资格在实际执行时检查。
音符键检查同步原始输入和防抖状态，避免在防抖窗口修改；同时等待触摸和歌曲包络释放完，避免尾音中途变调。
`REC_START` 期间及日志排空期间锁定映射；外部 `recording` 输入保留，并与内部录制忙状态共同保护。
映射仅存于 FPGA 寄存器：重新下载或断电后恢复默认，不写 Flash。

## 曲谱与日志扩展

`SONG_BEGIN`、`SONG_NOTE` / `SONG_CHORD`、`SONG_END` 保存音符/和弦/休止及其时长，支持暂存检查、按索引重发覆盖和失败保留旧谱。
`SONG_CHORD,index,mask,duration` 的 mask 为 MIDI60～72 的13位十进制音高位图；0为休止，145为C4+E4+G4。
有有效下载谱时，`PLAY` 或 S1/S2 推进曲谱时序；默认不进入发声通路。无有效下载谱时 `PLAY` 返回 `ERR,STATE`，S1/S2 不动作。

App v1.3 的 `AUDITION` 显式从头自动演奏下载谱，经同一七路触摸 DDS/ADSR 实时合成；普通 `PLAY`、S1/S2 曲谱操作和自动结束会解除试听，`STOP` 也会停止。录制期间禁止开始试听，曲谱仍需通过七键覆盖校验。不会播放预录采样，试听不作为赛题现场演奏验证。详见 [蓝牙曲谱协议](BLUETOOTH_MEDIA.md)。
开始/重启后有1500ms预滚，首条音符从屏顶下落到判定线；停止清空旧提示。安卓下载入口和安装说明见 [android_app/README.md](android_app/README.md)。
`STOP` 停止曲谱，仍按住的现场触摸音继续独立发声。

`REC_START` 上传键位映射和初始状态，随后发送按键/压力变化事件；`REC_STOP` 后等待 `REC_END,<丢失条数>` 再保存日志。
录制及日志排空期间锁定改键；64 条 FIFO 满时必须报告 `ERR,REC_OVERFLOW,<累计丢失条数>`。
以上记录不包含音频采样，导出的是演奏控制数据。完整命令、例子和边界见 [BLUETOOTH_MEDIA.md](BLUETOOTH_MEDIA.md)。

旧 `PCM_BEGIN`/`PCM_DATA`/`PCM_END`/`PCM_PLAY`/`PCM_STOP` 均返回 `ERR,CMD`；不再提供录音下载播放。
生产移除违规播放通路不等于整机赛题验收完成；自动曲谱试听也不能替代现场实时演奏。

## 板上验收

1. 在原音频工程生成/选择 `PCM5102_PAM8403.fs`，用 Gowin Programmer 的 **SRAM Program** 下载。
2. 上电后等待至少 600ms 校准，停止歌曲，松开 1～7 键并等待尾音消失。
3. 手机 App 的发送设置中，将“发送结束符 / 自动追加换行”设为 **LF**（CR 或 CRLF 也可以），关闭本地回显。发送 `PING` 时必须带真正的结束符，接收区应收到 `PONG`；随后发送 `MAP?`，应看到默认七音。只发送四个字母 `PING` 不会执行命令。
4. 发送 `MAP,1,67`，收到 `OK,MAP,1,67` 后按第 1 键，应听到 **Sol（G4）**。
5. 松开第 1 键后发送 `MAP_RESET`，收到 `OK,MAP_RESET`；再次按第 1 键，应听到 **Do（C4）**。
6. 按住音符键或播放歌曲时尝试修改，应收到 `ERR,BUSY`，音高继续保持。
7. 发送 `MAP,1,73`，应收到 `ERR,NOTE`；发送 `MAP?` 核对映射未变。

听音验收使用默认音量模式，或在压力音高模式保持轻压/未施压。
压力音高模式重压会将当前映射音降低一个八度，例如映射 C5 后重压可到 C4。

### 发送 PING 完全没有回复时

先检查发送结束符。FPGA 需要收到 LF（`0A`）或 CR（`0D`）才执行一行命令；
仅收到 `PING` 四个字母时会继续等待。不要在文本框中输入字面量 `\n`，那是两个普通字符。

如果之前已发送过未带结束符的文字，先单独发送一次结束符，结束积累的旧输入，再发送新命令。
旧输入若累计成 `PINGPING` 等内容，可能先收到 `ERR,CMD`；清空该行后重新发送 `PING` 加结束符即可。

若找不到 App 的结束符设置，但支持 HEX / 十六进制发送：关闭自动追加结束符，
先发送 `0A` 清空旧行，再发送 **`50 49 4E 47 0A`**，即 ASCII `PING` 加 LF。
必须使用 HEX 模式；不要把这些数字当普通文本发送。
正确返回为 `PONG` 加 CRLF（接收 HEX 为 `50 4F 4E 47 0D 0A`）。

仍无回复时，确认 Programmer 下载的是本工程的 `impl/pnr/PCM5102_PAM8403.fs`，
旧 UserCode `0x00009C48` 已因含预录 PCM 播放路径撤回；修正后的有效 UserCode 和 SHA256 以 [验证记录](VERIFICATION.md) 为准。同时检查 HC-05 TXD → J3 第 16 脚、RXD → 第 15 脚及共地。
SRAM 下载后断电会丢失本次配置，再上电需重新下载，或使用已另行配置的 Flash 启动文件。
手机需在 App 内实际连接 HC-05；仅在系统里完成配对还不能发送数据。
此音频顶层没有接入独立回显工程的 LED3/LED4 指示，不能用那两盏灯判断本工程是否收到字符。

### 已收到 PONG，但改键回复 ERR,CMD 时

`PONG` 已证明命令经 FPGA 处理后返回手机。`ERR,CMD` 表示收到一行，但格式或字符不符合协议；
忙碌保护会回复 `ERR,BUSY`，不使用 `ERR,CMD`。
当前命令必须是英文半角字符 `MAP,1,67`，没有空格；`MAP, 1, 67`、中文逗号或前后空格都会被拒绝。
终端显示看似一致时，仍需核对实际发送的字节，不能仅凭屏幕判断原因。

可直接用 HEX 模式复核：先单独发送 `0A` 结束旧行，等待可能出现的旧行回复；
再发送 **`4D 41 50 2C 31 2C 36 37 0A`**，即 `MAP,1,67` 加 LF。
期间停止歌曲、松开七个音符键并等待尾音消失，正常应收到 `OK,MAP,1,67`。
若仍为 `ERR,CMD`，保留这次固定 HEX 输入与对应回复，再排查下载版本和解析器。
