# 安卓 HC-05 曲谱助手

[仓库首页](../../README.md) · [文档索引](../../docs/README.md) · [下载当前 APK（v1.3）](dist/FPGA-Score-debug.apk)

原生 Java App，连接现有 **HC-05 经典蓝牙 SPP**。下载的是音符、和弦、休止与时长，不包含 PCM、MP3 或 FLAC。`PLAY` 开始 HUB75E 曲目指引；FPGA 实时合成触摸、APDS-9960 手势和单弦吉他声音。App 另提供手势音源设置和单次拨弦控制。

## 安装和第一次使用

1. 将 `dist/FPGA-Score-debug.apk` 复制到安卓手机并安装。支持 Android 10+；这是本地调试签名安装包。
2. 先在手机系统蓝牙设置中配对 HC-05，PIN 以模块实际配置为准，常见为 `1234` 或 `0000`。
3. 打开“FPGA 曲谱助手”，Android 12+ 允许“附近的设备”权限。App 只读取已配对设备，不扫描附近设备，不需要定位权限。
4. 点击“刷新已配对设备”，选中 HC-05，然后“连接所选设备”。连接完成会先 `PING`，再读取实际七键映射。
5. 载入“小星星”示例或导入本地 CSV / MIDI；查看条数、总时长与所需音高。
6. 点击“校验键位并下载”。App 先重新读取 `MAP?`，确认七键覆盖所有所需音高，再逐条发送并等待确认。**进度 100% 且显示已提交，才代表 SONG_END 校验成功。**
7. 想听开发板自动演奏，点击 **“自动演奏 · 已下载曲谱”**，预备 1.5 秒后开始，无需按触摸键，曲谱结束自动停止；`STOP` 可以提前停止。此功能需要 v1.3 配套 FPGA 位流，旧位流会提示尚不支持。
8. 想自己演奏，点击 `PLAY · 开始指引`，屏幕先预备 1.5 秒，再开始无声曲谱指引。按实际触摸键演奏；`STOP` 停止指引。曲谱下载完成后可以断开手机，使用板上 S1 开始/停止曲谱；S2在XY页之外短按从头重启，XY页短按选图，长按约1秒切换显示页。

下载内容保存在 FPGA RAM，掉电需重新下载。下载中断、校验失败时，FPGA 保留原有效曲谱。若断开恰好发生在 `SONG_END` 已提交而手机尚未收到确认时，新谱可能已生效；重连后完整重传即可。

## 自动演奏试听（v1.3）

新按钮发送 `AUDITION`，从头演奏**板上已提交**的曲谱；只在手机上载入/导入新曲谱不会更新板上旧谱。没有有效曲谱时先下载。自动演奏在 FPGA 内使用与七个触摸键相同的独立 DDS、频率、ADSR、混音与 I2S 通路，支持所映射的七音和弦、休止及连续重复音；当前触摸音色、ADSR、逐声部滑音和 FSR 表情设置会影响试听。没有新增录音/PCM播放器。

自动演奏与触摸共用七个声部，同一键被按住时保持该声部，不额外叠加一份自动音。`STOP` 释放曲谱占用的门控，按住的实际触摸键继续发声；包络可保留短释放尾音。再次点击自动演奏从头开始。点击 `PLAY`、板上 S1/S2 曲谱操作或曲谱结束均解除自动模式；S2长按切显示、XY页短按选图不改变播放。蓝牙断开后已开始的自动演奏继续至结束，掉电后曲谱和模式都清空。事件录制期间禁止开始自动演奏。

赛题现场验证仍使用传感器实时演奏。自动试听用于核对下载谱、节奏和硬件合成通路，不能代替两维交互、≥4/32可闻独立声部或≤10/5ms延迟的实测证据，也不据此宣称整机已满足全部要求。

## 七声部独立滑音（v1.2）

“七声部独立滑音”卡片有七个滑杆，分别对应触摸OUT1～OUT7，范围±1200音分（上下一个八度）。按住和弦可只调其中一个音；FSR全局滑音继续叠加。连接时合并拖动并约100ms逐条确认最新目标，不发送排队旧位置；断线为草稿，重连后需点击“发送全部音高”。“全部回正”恢复七个目标到0半音。

编辑值与已确认目标分开显示，FPGA平滑过渡。板子复位后归零；断开手机不撤销板上设置。只支持七个固定触摸声部，红外/手势动态声部和吉他没有逐声部滑杆；事件日志不记录此变调。App蓝牙调参不作为赛题≤5/10ms延迟证明。需同时更新本次FPGA位流。协议、时隙与验收见[逐声部滑音](../VOICE_PITCH.md)。

## 外观设置（v1.1）

首页顶部点击 **“外观设置 · 更换背景”**，可从安卓系统文件选择器选择手机图片作为背景。背景固定铺满屏幕并居中裁剪，功能卡片在上方滚动；竖版图片通常更适合手机屏幕。

- **背景遮罩**：拖动滑块可实时调整背景变暗程度，让背景与文字更协调。设置自动保存。
- **选择背景图片**：图片在独立后台线程中缩放处理，长边最多 2048 像素，总像素不超过 400 万，随后保存到 App 内部；重启后保留背景，原图移动或删除不会影响已保存的背景。无需申请相册或整盘存储权限。只接受可完整解码的静态图片。
- **恢复默认背景**：删除 App 内的背景副本，恢复默认渐变背景和遮罩设置。

蓝牙、曲谱、七键配置、手势音源和日志改为圆角卡片布局，主要操作使用蓝紫色按钮。更换背景不会重建界面或主动断开蓝牙；图片处理与蓝牙通信使用不同线程。卸载 App 或清除应用数据会删除自定义背景。

## 曲谱格式和容量

- 单条记录：MIDI 60..72（C4..C5）内一个或多个音符，或休止；1..60000ms。
- 最多 128 条。长于 60000ms 的事件会拆成多条，总条数仍不能超过 128。
- 七个实体键必须覆盖整首曲谱的不同音高；若需要超过七种音高，固定七键映射无法全部覆盖，App 会明确拒绝下载。请制作适合七键的曲谱。
- 当前只表达音高、并发关系、起止与节奏。MIDI 力度、音色、表情不映射到 FPGA 音色；延音踏板、非中心弯音、鼓轨、SMPTE 时间码及超范围音高会明确拒绝，不能静默裁音。

### CSV

UTF-8，首行可选 `pitches,duration_ms`。每条 `音符,毫秒`，和弦用 `+`，`REST` 或 `0` 为休止。支持 `#` 注释行。不使用十六进制掩码作为导入格式。

```csv
pitches,duration_ms
60+64+67,500
REST,250
62+65+69,500
60,1000
```

可直接使用 `samples/twinkle.csv` 或 `samples/chords_and_rest.csv`。

### MIDI

支持标准 SMF 类型 0/1、PPQ 时间基准、tempo 变化、Note On/Off、同 tick 和弦以及休止。合并所有轨道的实际音符，不自动选旋律、转调或删去伴奏。请从制谱软件导出要演奏的声部，确保范围 C4..C5，并尽量将总不同音高控制在七种以内。

音符边界按实际 tempo 换算到毫秒；不足 1ms 而无法保留的边界会拒绝。文件上限 2MB。MIDI 乐器/力度不影响下载的屏幕指引。当前下载格式保存每段的音高集合与时长，没有逐键 Note On/Off 标记；和弦组成变化时，跨段持续的音可能再次显示音符头，不等于要求重新按下该持续键。

## 协议

使用 RFCOMM SPP UUID `00001101-0000-1000-8000-00805f9b34fb`。发送 ASCII，每条以 CRLF 结束；命令内容不超过 62 字符（含 CRLF 不超过 64）。

```text
PING                         -> PONG
MAP?                         -> MAP,60,62,64,65,67,69,71
MAP,1,60                     -> OK,MAP,1,60
MAP_RESET                    -> OK,MAP_RESET
SONG_BEGIN,3                 -> OK
SONG_CHORD,0,145,500          -> OK  (C4+E4+G4)
SONG_CHORD,1,0,250            -> OK  (休止)
SONG_CHORD,2,128,1000         -> OK  (G4)
SONG_END                     -> OK  (校验并原子提交)
PLAY                         -> OK  (1.5秒预备，然后指引)
STOP                         -> OK
GUITAR                       -> OK  (单弦吉他拨弦一次)
TONE,0                       -> OK  (手势正弦音色)
VIBRATO,1                    -> OK  (开启手势颤音)
BANK,1                       -> OK  (手势高音组 G4～C5)
```

`SONG_CHORD` 的 mask 是**十进制** 13 位音高位图：bit0=MIDI60，bit12=MIDI72；它不依赖实体键编号。旧 `SONG_NOTE,index,note,duration` 由 FPGA 保持兼容。

App 一次只保留一条待确认命令。4 秒未收到预期响应、设备返回 `ERR,...`、断连或用户取消，都停止下载并关闭本次连接。协议没有命令序号，因此不在同一连接盲重发，避免迟到 `OK` 被错认成下一条回复。点击连接，再点击“重新下载”会从 `SONG_BEGIN` 重发整个暂存曲谱。索引写入与最终原子提交由 FPGA 保证。

## 手势音源与单弦吉他

“手势音源与单弦吉他”区域分别选择并应用音色、颤音与音符组；每次应用使用同一条串口命令队列，并等待 `OK` 后才提示成功。下载或其他命令执行期间，这些按钮与现有操作一起禁用。列表显示待发送值，没有设备状态查询；连接后需要点击应用，不能把列表初始值当作板上当前状态。

- `TONE,0..4`：依次为正弦、钢琴、长笛、尤克里里、鼓。
- `VIBRATO,0/1`：关闭或开启颤音。
- `BANK,0/1`：低音组 C4～F4，或高音组 G4～C5。
- `GUITAR`：点击一次触发一次固定单弦吉他拨弦，不需要 APDS-9960 就绪，不选择和弦或吉他弦。

`TONE` 和 `VIBRATO` 影响当前红外/手势共享音源，`BANK` 只改变手势音符组；这些设置不修改七个触摸键的 MIDI 映射、触摸压力表达或下载曲谱。板上 S1/S2 的曲谱操作见 [屏幕说明](../AUDIO_VISUAL.md)。命令均返回 `OK`（CRLF 结束）；数字超出范围返回 `ERR,RANGE`，缺失参数或格式错误返回 `ERR,CMD`。App 使用有限选项生成命令，避免输入错误。

## 键位与演奏事件日志

键位配置输入框按第 1..7 键顺序填写七个 MIDI 数字，点击“应用七键映射”。此操作顺序发送七条 `MAP`；若中途失败，部分键位可能已改变，重新连接后会读回真实配置。录制期间 App 禁止改键、下载；FPGA 同时负责锁定配置。

`REC_START` 后将设备的 `MAP`、初始状态及后续 `EVT` 保存到 App 内存。`REC_STOP` 后等待接收窗口出现 `REC_END,0`，再“导出事件日志 .txt”。`OVF` / `OVERFLOW` 或非零 `REC_END` 表示缓冲溢出，日志不完整。断连、未停止就导出、App 内存日志达到上限，也会在文件头标记 `complete=false`。导出使用安卓系统文件选择器，不申请整盘读写权限。

这是触摸键与压力的**演奏事件日志**，不是音频录音。红外/手势事件、吉他拨弦、音色/颤音/音符组、ADSR和逐声部变调设置不包含在日志中；录制期间仍可使用这些新控件，因此日志不能完整重放含手势或吉他的混合演奏。保持 App 在前台，App 退出会断开蓝牙；尚未导出的日志随进程退出丢失。
