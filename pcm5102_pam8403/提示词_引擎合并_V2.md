## 2. 已核验事实与旧结论更正

### 2.1 传感器帧预算

现有 `src/tdm_synth.v` 的周期公式为：

```text
T = 16×V + 11×E + 2×C + 23

V：实际遍历的声部数量。
E：本帧实际完成 EVENT_COMMIT 的音符数量。
C：本帧实际执行 COMMAND_FETCH 的命令数量。
口径：包含接受 sample_ce 的时钟沿和发布输出的时钟沿。
```

首次 `VOICE_PRIME` 实际等待 17 拍；读取新命令还需要额外周期。TEST32 是一条命令展开为 32 个音符，不能与 32 条独立事件视为同一种最坏负载。

| 场景 | 周期 | 1024 拍内余量 | 证据类型 |
|---|---:|---:|---|
| 当前 32 声部，无事件 | 535 | 489 | 工程内基线用例已复现 |
| 当前 32 声部，TEST32 | 889 | 135 | 同上 |
| 当前 32 声部，32 条独立事件 | 951 | 73 | 同上 |
| 48 声部，32 音 TEST32 一帧完成 | 1145 | −121 | 按现有调度外推，未实现 |
| 48 声部，32 条独立事件 | 1207 | −183 | 按现有调度外推，未实现 |
| 48 声部，TEST32 首帧只展开 16 音 | 969 | 55 | 按现有调度外推，未实现 |
| 48 声部，16 条独立事件 | 999 | 25 | 按现有调度外推，未实现 |
| 48 声部，12 条独立事件 | 947 | 77 | 按现有调度外推，未实现 |
| 48 声部，8 条独立事件 | 895 | 129 | 按现有调度外推，未实现 |

**最后六行不是共享引擎的实测预算。** 尚未计入新增加的触摸控制、数据格式转换、混音归一化和发布周期。新的上下文/调度改变后应重建公式。

现有 context 预取每声部要读 16 个 36 位字；只删除 `LOOK_AUX2` 不能保证吞吐提高，还可能遗漏该状态承担的 RAM 写入。必须同时证明计算依赖、读写时序和下一声部数据已就绪。

### 2.2 触摸帧预算

现有触摸常规通路每声部为 47 拍；启动沿和三拍 PUBLISH 共 4 拍。每次段切换增加 16 拍除法：

```text
T_touch = 16×47 + 4 + 16×发生段切换的声部数
        = 756～1012 拍
```

`FX_PREFLIGHT_20261024.md` 已报告真实顶层压力场景的最大值 1012 拍。旧文档的 1024 是静态误算，不是需要接受的测量误差。两引擎当前并行，不能把各自忙碌周期简单相加作为现有系统的串行预算。

### 2.3 满池行为

`tdm_synth` 已经有最老声部替换：空闲优先，满池选择 `rank_order[VOICES-1]`，随后进入 pending 替换流程。`overrun` 检测 FIFO 容量溢出和帧 deadline，满池本身不会直接触发它。

`sim/tb_tdm_queue.v` 已覆盖最老声部替换。因此问题不是“从零补抢占”，而是共享后如何继续保护触摸键及保持两类替换行为。

### 2.4 ADSR 与精度

`adsr_config` 已有串行除法器，触摸配置请求也会计算 `sa/sd/sr`，只是 `touch_config` 提交时未输出它们。优先评估复用这些结果，不能把新增完整除法器当成既定成本。

触摸包络为 16 位，传感器包络为 9 位。24 位相位累加插值也不自动等价于原触摸的商/余数误差累加。**保留 16 位寄存器，不等于已证明包络等价。** 必须比较每个采样值、段边界、任意电平松键和重触发。

默认值、restore、串口配置、录制快照和回放配置都必须拥有对应的步长。原触摸 64 位回放数据没有步长，不能只接串口配置模块输出而忽略回放。

### 2.5 ROM 与参数耦合

- `touch_sine_rom` 是 1024×16；传感器正弦表是 256×16。
- 逐点检查确认 `sensor_table[i] == touch_table[4*i]`，共 256 点一致。
- 可考虑一张 1024 点 ROM：触摸索引使用 `phase[31:22]`；传感器使用 `{phase[31:24],2'b00}`。须覆盖基波、谐波、辅助振荡器及 LFO，并保持同步读取延迟。
- TEST32 当前结束条件依赖 `VOICES-1`，而频率索引只有 5 位。总槽数改 48 时必须仍只生成 32 个不同测试频率。
- 5 位只能表示 0～31。共享槽地址至少 6 位，48×16 字地址至少 10 位。传感器本地槽号可保持 5 位，触摸本地键号保持 4 位。
- 外部 `POLY` 当前只允许 1、2、4、8、16，语义继续只作用于触摸。无需把协议扩成 48。

### 2.6 资源证据

`FX_PREFLIGHT_20261024.md` 的冻结基线报告为 Logic 21963 / CLS 11300 / Reg 10442 / BSRAM 47 / DSP 26.5，setup/hold 最差 slack 为 +0.036/+0.151 ns。它是已有快照，不自动代表后续工作区。

该报告已否定“downloadable_song 去重必省 350～450 CLS”。同样，不能以固定 Logic/CLS 比例兑现本次合并收益。删除触摸主乘法器有回收 DSP 的可能，但最终数量取决于扩位、映射和新增运算资源，必须看完整工程报告。

## 3. 推荐架构

### 3.1 固定分区，共享执行

逻辑上固定 32 个传感器槽和 16 个触摸槽。共享调度器可统一编号 0～47；固定分区并不要求两类 context 采用相同字段格式或占用同一块物理 RAM。

```text
红外/手势/TEST32 → 原事件队列 → 传感器 32 槽 ┐
                                                  ├→ 共享调度/乘法/ROM
触摸 gate/physical/pedal/弯音 → 触摸固定 16 槽 ┘
                                                        │
                        ┌───────────────────────────────┴──────────┐
                 sensor_sample                              touch_sample
                  原传感器后级                    原触摸归一化、压力及混音后级
```

传感器分配和最老声部替换只在自己的 32 槽中进行；触摸键按键号直接定位。触摸的 `age/oldest/victim/protected_limit` 仍用于触摸尾音管理，不承担传感器抢占。

触摸 gate 不必绕经传感器事件 FIFO。每帧原子快照按键、物理状态、踏板和音高输入，在固定槽扫描中处理起音及松键。这可以避免传感器突发阻塞触摸输入。

### 3.2 两路混音语义

分别输出 `sensor_sample` 和 `touch_sample`，保留各自的累计位宽、右移、截断、饱和顺序及固定流水延迟。

- 触摸 normalizer 继续按触摸声部计数，范围 0～16；不按总数 48 重算。
- 压力音量仍作用于触摸分支，不能因为共享核心而影响传感器音量。
- 保留触摸前七键与高九键不同的衰减、音高来源和调制方式。
- 保留传感器 tuning/vibrato 与触摸 FSR/逐键弯音的作用范围；不能给触摸重复施加已经算过的调音比率。
- 两路结果必须在下一个消费它们的帧沿之前稳定；不能只检查最终合成总周期。

### 3.3 调度初始选择

首个原型从传感器 `EVENTS_PER_FRAME=8` 开始评估，保留可配置的 12 档用于对比；16 档仅在全部通路实测有余量后再考虑。

明确三个独立常量：`SENSOR_VOICES=32`、`TOUCH_VOICES=16`、`TEST_NOTES=32`。TEST32 跨帧续发不能因总槽数变化而多发或重复频率。

配额 8 时，空队列的 TEST32 需要四个采样帧完成分配，首末批相差三个帧周期，即 61.44 µs；实际起音还包含既有 pending/流水延迟。不能把该数当作所有排队负载的延迟上限。需要分别量化普通事件、满队列、TEST32 和触摸输入的端到端延迟。

首轮工程目标为完整功能最坏占用不超过 960/1024 拍；这是拟定的 64 拍余量目标，不是现有设计保证。硬性 deadline 为下一个帧沿前提交输出。若只能满足硬限制却无目标余量，报告原因和可选调度，不能宣称已留足扩展空间。

### 3.4 上下文与包络设计决策

在编码共享核心之前交付：

1. 两类 context 的逐字段位宽、符号、范围、初始化值、更新状态和写入字位置。
2. RAM 的实际深宽、端口安排、预取/写回重叠和最坏冲突表。现有传感器有效载荷已占 556/576 位，不能无限追加触摸字段。
3. 主乘法器每拍操作数和结果消费点；比较共用的 33×18 路径是否容纳触摸的增益与包络运算。
4. 两种触摸包络候选的数值与周期结果：复用配置步长的高精度插值；保留原误差累加语义并把段转换计算移出关键扫描。不要默认二者等价或默认后者必然省资源。
5. 固定踏板四段、快速阻尼及动态缩短释放段的处理办法。只有 A/D/R 三个步长不足以自动覆盖全部段切换。

默认以原触摸逐采样结果为参考。传感器除已明确列出的跨帧起音调度外应保持逐样本一致；触摸若产生数值差异，先给出最大/RMS 增益及 PCM 误差、边界时长和频谱变化，再确定是否可接受。不得通过修改旧测试期望值隐藏未解释的差异。

允许保留小型独立段准备逻辑，但要计入 LUT/FF/DSP 和完成期限；不能把并行后台计算当作零成本。也不能仅凭“合并”二字要求所有 RAM、配置转换和算术都串行化。

## 5. 必测行为矩阵

| 场景 | 必须检查的结果 |
|---|---|
| TEST32 与 16 键同帧开始 | 32 个不同传感器频率、16 个触摸槽均存在；记录首末起音帧 |
