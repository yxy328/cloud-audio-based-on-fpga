# 独立演奏录制、Flash 保存与回放：完整说明

2026-10-19。录制对象是演奏控制事件，不是麦克风音频，不生成 WAV。

唯一交付烧录文件为包根目录的 **FINAL_EVENT_RECORDER.fs**。源码、工程、约束、测试及报告都在同一个“独立录放_完整工程”文件夹内，不需要从其他工程拼接。此前的 PCM5102_PAM8403.fs 不包含本次功能。

**验证状态：RTL 仿真、整机综合、布局布线及所列时序检查通过；没有自动烧录，没有实物听音、Flash 读回和实物断电试验。** 文档依据、运行时保护与实物待确认项分别说明如下。

## 2. 完全脱离手机的操作步骤

将 TTP229 模块设为 **16 键、多键、低有效串行**，改硬件选项后重新上电，松开全部键完成约 600 ms 校准。不同模块的焊盘标注可能不同，应核对本模块的 KYSEL、多键、SAHL；本目标默认极性对应已有参考接线的 TP1 开路。

SCL → F6 / J3 第 37 脚；SDO → F7 / J3 第 38 脚；共地。进入串行模式前，拆除 OUT1～OUT8 原直连线，以及 SCL 到电源／地的固定连接。其余音频、屏幕和传感器按当前工程接线保留。

| 输入 | 操作 |
| --- | --- |
| K1～K12 | 演奏及多键和弦；前七键保留映射／独立变调，K8～K12 为已有高音键 |
| K15 | 开始录制；已有 RAM 或 Flash 内容时先显示 C1 覆盖确认 |
| 松开后再次按 K15 | 在 C1 状态确认重新录制 |
| K14 | 停止录制／回放；空闲时取消待确认操作 |
| K13 | 回放 RAM，包括刚停止、尚未保存的内容 |
| K16 | 单独保存已经停止的 RAM 录制 |
| K14 + K16 | 空闲时请求删除，显示 C2；松开后按 K16 确认，K14 取消 |

所有录、停、存、放、覆盖和删除都不依赖手机或 S1/S2。播放／录制时 K14 与其他控制键重叠也优先停止。按住控制键只产生一次命令；忙时不启动冲突操作，重复保存已成功的同一份内容不会再次擦写。

操作顺序：

1. 按 K15；若显示 C1，松开后再次按 K15 确认。
2. 用触摸、红外或手势演奏，压力／滑杆继续影响原音源并被记录。
3. 按 K14 停止。**停止只保留 RAM，不自动保存。**
4. 可立即按 K13 回放；K14 停止回放并清除音源及音效尾音。
5. 按 K16，等待 B1 结束，确认 S1 且 E0 后再断电。
6. 重新上电只读检查并加载有效录制；键盘校准完成后直接 K13 回放，无需手机。

确认重新录制会替换 RAM 工作副本，旧 Flash 持续保留到新保存成功。未保存就断电，重启恢复旧的成功版本。空录制不会覆盖旧 Flash。只有一份用户录制；两个槽用于提交保护，不是两个可选曲目。

## 3. 点阵屏与错误状态

在总览页，存在录制状态／错误时覆盖第 1、2、7、8 行，保留键态及 ADC 行。其他图形页仍保留，可用原显示切页操作返回总览。

| 字段 | 含义 |
| --- | --- |
| R1 / P1 | 正在录制 / 回放 |
| B1 | 正在检查／保存 Flash，请等待实际结果 |
| A1 | RAM 可回放；不代表已断电保存 |
| Txxxxx.x | 经过时间，秒与十分之一秒 |
| S1 | 当前 RAM 已提交 Flash 并读回校验成功 |
| F1 | 容量／时间满，自动停止；仍需 K16 保存 |
| E0 | 无错误 |
| C1 / C2 | 确认覆盖 / 删除 |
| 最后一行 E... C400 | 已用事件数／容量 1024，十六进制 |

| 错误 | 含义 |
| --- | --- |
| 3 | 时间轴格式损坏，停止回放并清音 |
| 4 | 没有内容，包括仅静音的空录制 |
| 5 | 存储适配器未给出具体原因的失败 |
| 6 | 同一种一次性触发在 1 ms 内重复，无法无损表示；此次录制无效，现场演奏继续 |
| 7 | 录制边界／处理期限异常 |
| 8 | JEDEC 不符或目标槽含未知／未完成数据，禁止对应擦写 |
| 9 | 写使能失败，或约 2 秒存储看门狗超时 |
| A | 正文／头部读回校验失败，不报告保存成功 |

保存失败时，已结束的 RAM 录制仍可回放及重试保存。不要把命令 OK、A1 或停止状态当作 S1。

## 4. Flash 分区、完整性与断电保护

以下是**本工程新定义的分区**，不是声称原板已有这些空闲地址。配置保持单镜像、起始地址 0。

| 地址 | 处理方式 |
| --- | --- |
| 0x000000～0x7FBFFF | 录制控制器硬性禁止擦写，包含配置固件 |
| 0x7FC000～0x7FDFFF | 8 KiB 槽 A，运行时证明空白／本格式归属后才可擦写 |
| 0x7FE000～0x7FFFFF | 8 KiB 槽 B，同样逐槽检查 |

最终位流二进制负载 **928436 字节**，低于录制分区起点。这里计算的是 .fs 的二进制负载，不是 ASCII 文件长度。tools/check_take_layout.py 核对器件、位流边界及单镜像设置，也可用 --dump 离线检查完整 8 MiB 原始读回文件；它不连接下载器、不擦写硬件。

运行时保护：

1. 先只读 JEDEC，只接受 EF4017；其他兼容型号也不会未经验证自动放行。
2. 只读扫描全部 16 KiB。槽须全 FF，或本格式、CRC 正确且填充区空白，才取得擦写权限。未知内容不擦除。数据有效性与擦除权限分别判断。
3. SPI 底层另行检查地址、页边界、长度及授权；没有整片／大块擦除命令，不接收手机指定任意地址，不自动解除芯片写保护。
4. 保存写另一合格槽；轮询 WEL/WIP，正文 CRC 读回、头逐字节读回，最后单独写提交字节并再次核对。成功前保留上一份提交。
5. 上电选 CRC 正确、已提交且代数最新的版本，载入 RAM 再次校验。删除提交一份新代数空记录，避免正常重启后旧记录复活。

每槽 16 字节头：FPT1、16 位代数、事件数及 FULL、24 位时长、CRC32、提交字节。正文从偏移 256 开始，整数及 48 位事件为小端。CRC32 多项式 EDB88320，覆盖头前 11 字节及全部正文；提交字节最后由 FF 写为 00。

模型验证了新槽正文写入被中断时仍恢复旧成功版本。**无法识别的未完成槽保持锁定，本版不自动修复。** 应先完整读回、备份和核对后人工处理，不能直接整片擦除绕过保护。真实电压跌落、擦除中断和芯片掉电行为尚未实测。

手动烧录：核对实际板卡与 Flash 后，在 Gowin Programmer 选择 GW5A-25A，加载包根目录唯一的 FINAL_EVENT_RECORDER.fs，配置镜像起始地址为 0。需要断电后仍启动本固件时，使用 External Flash Mode 并按实际识别的 Flash 配置；不要猜芯片型号。JTAG/SRAM 下载只适合临时测试，本身不能让配置固件断电保留。随后按第 2 节完成录制、保存、断电再上电及 K13 回放验收。

首次烧录与以后升级都由你手动完成。Programmer 的整片擦除会删除录制区；升级前先备份并核对下载操作。录制区地址不能作为配置 .fs 下载地址。

## 5. 事件内容、容量与实现入口

RAM 上限 **1024 条 × 48 位 = 6144 字节**，另有历史比较 RAM。每条为 24 位毫秒时间、8 位字段、16 位值，时间分辨率 1 ms。每组开始最多等待一音频帧，随后原音源下一帧读取完整参数；事件时间到该采样的调度上界约 40.96 µs，另有原合成与 I²S 流水线。

记录实际触摸音高／变调、触摸及传感器 ADSR、压力增益、音高比例、总音量、音效／湿度、音色、音组／八度、颤音、12 键门控及红外／手势／吉他／TEST32 一次性触发。和弦保存为门控位图及同一时刻的触发组。

录制先冻结完整控制组再串行写入，避免多字音高新旧混合。回放把每组更新安排在音频帧刚采样之后，最多 3×34=102 个时钟（2.04 µs）内完成，早于下一帧的 1024 时钟边界；门控及一次触发在 FE 提交，原音源下一帧读到完整参数。仿真断言禁止组跨越音频帧。FF 或停止清除门控、待发触发、声音及音效尾音。没有另换声音合成模块。

初始配置占 34 条，后续只记变化，并给结束组留余量。容量按变化次数计算，**不是固定秒数或固定音符数**：稳定长音可较长，持续压力变化、多声部滑音会更快耗尽，极端情况下可能只有几十至几百毫秒，不能承诺长时间连续录制。满后保留可回放前缀并停止，按 K16 才保存。24 位时间约 4.66 小时也按满处理。

主要入口：

- src/performance_take.v：时间轴、RAM、整组快照／提交、回放、确认、容量与错误。
- src/take_key_control.v：K13～K16 板上控制。
- src/take_nor_store.v：双槽、CRC、读回、提交、上电恢复及删除。
- src/take_spi_transaction.v：SPI 位时序与独立命令／地址保护。
- src/top_take.v、PCM5102_EVENT_TAKE.gprj：完整独立目标及顶层连接。
- src/top.v、hc05_keymap.v、hub75e_status.v 等：接入现有音源、可选串口和点阵状态。

HC-05、原演奏／键位／ADSR／音效／显示控制保留。可选命令 TAKE_REC、TAKE_STOP、TAKE_SAVE、TAKE_PLAY、TAKE_DEL、TAKE_YES、TAKE_NO 以换行结束。TAKE? 返回 TAKE,FF,E,TTTTTT,CCC,DDDDDD，依次为十六进制标志、错误、经过毫秒、事件数、总时长。标志由低到高为录、放、RAM 可用、Flash 已保存、满、存储忙、两位确认。OK 只表示请求已接收。

本独立目标用板上事件录放替代旧七键 ASCII 日志及 PCM/WAV 上行，以回收资源；保留原音色、32 声部、HC-05、压力、音效及 HUB75E 图形。8 键直连代码保留，但四个板上控制键需要 16 键模式。包内不需要安装 APK。

## 7. 参考仓库及尚未完成项

核对了用户给出的 [fpga-musical-magic-box](https://gitee.com/xu-qianru/fpga-musical-magic-box) 在工作区已有的较新版副本；README 写明“掉电恢复默认参数，不写入 Flash”，脱机曲目为内置乐谱。在线页面当时无法读取，不能据本地副本断言远端最新版功能。其复音及资源共享思路可参考，未假设它的 TFT／触摸屏或存储接口存在于当前工程。

上一版超限是实现需要优化，不能据此判断这块 FPGA 无法录放。本版共享包络／谐波运算、精简声部排序与中间状态、串行 CRC，并固定源码构建验证，没有减少八种音色或 32 声部。

**尚未完成实板验收：** 核对实际板卡／Flash、首次读回、真实擦写与断电、连续压力／滑杆演奏、模拟输出延迟与听音。没有自动修复未知未完成槽、多曲目管理和长录制流式存储。

若实板 Flash 型号／接线不符，需要该板原理图与读回信息后适配；若配置 Flash 无法安全共享，应增加独立 **3.3 V SPI NOR 模块**，使用至少 CS/SCLK/MOSI/MISO 四根空闲 FPGA IO，重新核对约束。本版没有把 RAM 冒充断电保存，也没有宣称实物已经验证。
