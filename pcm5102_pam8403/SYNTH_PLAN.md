## 1. 选择的方案

采用四路独立 DDS 波表振荡器，每路配独立 ADSR 包络、音高和音量控制，再经过实时混音、缩放及饱和处理，送入现有 I2S、PCM5102 DAC 和 PAM8403 功放。

整个音频运算通路使用 Verilog 硬件逻辑。上位机可用于生成数学正弦表、仿真和检查结果，运行时音频生成不依赖 CPU 或软件逐样本计算。

波表只存一个周期的数学正弦幅值，按音高控制的相位累加器逐样本寻址。没有歌曲 PCM、录音文件或整段音频缓冲。当前试听版按预设曲谱定时生成音符事件；参赛实时演奏目标仍以现场输入替换该曲谱控制。后续可在同一个声部接口上增加加法合成或 FM。

## 2. 音频数据通路

```mermaid
flowchart LR
    K[实时演奏输入] --> E[同步与音符事件]
    E --> A[声部分配与参数寄存器]
    A --> V[4 路独立 DDS 与 ADSR]
    V --> M[加宽混音 / 固定缩放 / 饱和]
    M --> I[I2S 发送]
    I --> D[PCM5102 DAC]
    D --> P[PAM8403 与喇叭]
```

使用现有 50MHz 主时钟，所有内部逻辑在同一主时钟域，通过采样使能更新音频。保留 BCK=3.125MHz、LRCK=48,828.125Hz；每个音频采样周期为 20.48µs，相当于 1024 个主时钟周期。

每个声部包含独立的：音符标识、门控状态、32 位相位累加器、可写相位步进、ADSR 状态和包络幅度。音高计算为：

`phase_inc = round(frequency_hz * 2^32 / 48828.125)`

第一版采用有效 1024 点、16 位有符号正弦表，可用四分之一周期表和象限映射实现。四路并行查表需要分别可读的 ROM 实例或相应存储端口，具体资源以综合报告为准。

演奏期间修改某一路相位步进，实现该音实时变调；变调时保持相位连续。ADSR 参数也独立存储。
参数为 Attack=2ms、Decay=80ms、Sustain≈60%；现场触摸音 Release=10ms，歌曲仍为 100ms 以配合曲谱间隔。此前固定和弦版用 500ms 释放。

按下立即进入 Attack，按住停留在 Sustain，松开进入 Release，包络降到零才释放声部。起音不等待 Attack 完成。

四路包络后的 16 位有符号样本采用加宽累加，至少需要 18 位；计划使用 24 位中间混音值，固定缩放并饱和到 16 位输出。不会随正在发声的数量突变整体缩放比例。首次上板使用低总音量。首版左右声道输出相同混音样本。

声部分配优先选择空闲声部，其次选择正在释放的声部，全部占用时按明确的最旧声部策略处理第五个音。首版保证四个独立声部，接口保留扩展能力。

## 3. 输入与延迟约束

独立触摸顶层 `ttp229_gpio/src/ttp229_gpio_top.v` 的 `DEBOUNCE_MS=20`；当前音频顶层已为 1～7 键改用 2ms 确认，8 键保持 20ms。

[TTP229-BSF 数据手册第 5 页](https://www.tontek.com.tw/uploads/product/97/TTP229-BSF_V1.1_EN.pdf)给出正常工作输出响应典型值：8 键 16ms，16 键 32ms；休眠唤醒的典型值也随扫描率变化。它不能据此保证从实际触摸开始到声音输出 ≤10ms，缩短 FPGA 读取周期不能消除芯片内部检测时间。

因此首版以四路独立 GPIO 演奏信号作为性能验收入口。机械按键需要同步、短确认及防重复触发，并实测触点抖动；前端处理预算 ≤2ms。S1 可继续作为单音调试输入，四路独立按键的物理引脚须在整机约束核对后确定。若最终必须使用触摸输入，需要选择并实测满足整机延迟要求的控制器。

TTP229 当前以 OUT1～OUT8 直连作为功能演示入口，TP2 开路、TP3/TP4 短接开启多键；不使用 F6/F7 串口。
OUT1 改用 K4/J3 第 5 脚，避免与 DAC LRCK 的 K1 冲突。实际触摸到声音的总延迟仍须实测。

设计预算与最终实测结果分开记录：

| 环节 | 设计预算 / 已知参数 |
| --- | --- |
| GPIO 同步、确认与事件生成 | ≤2ms，输入抖动须实测 |
| 声部分配、DDS、ADSR、混音与 I2S 帧等待 | 目标 ≤0.1ms |
| PCM5102A 数字滤波 | 普通滤波约 22 个采样周期，即约 0.45ms；低延迟滤波约 3.5 个采样周期 |
| 功放、静音恢复及模拟输出 | 上板测量，纳入总延迟 |
| 控制信号到模拟输出 | 验收 ≤10ms，尚未验收 |

I2S 时钟持续运行，DAC 保持解除静音；音符开关由包络完成。仍须实测长时间静默后的首次起音，确认 DAC 自动静音恢复没有造成超时。

## 4. 分步实施与验收

| 步骤 | 实现内容 | 通过条件 |
| --- | --- | --- |
| 1 | 参数可写的单声部 DDS，接现有 DAC 通路 | 现场演奏事件触发发声；修改音高立即改变输出；确认 DAC 模拟输出和喇叭确实发声 |
| 2 | 单声部 ADSR，加入门控和音量 | 按下起音、按住持续、松开渐弱；包络时长和幅度可检查，快速重触发行为明确 |
| 3 | 四路独立声部与加宽混音 | 四个音同时存在；单独改变或释放一个音不改变其他声部参数；最大叠加无数值回绕 |
| 4 | 实时音符事件、四声部分配及演奏输入 | 同时按四键能形成四音和弦，释放某键只释放对应声部，支持演奏中单声部变调 |
| 5 | 时序收敛、整机延迟与项目交付 | 仿真和综合通过，上板测量 ≤10ms；交付源码、约束、仿真、接线、资源及验收记录 |

步骤 1～3 已合入当前原工程；四个固定声部槽位独立运行包络，参数当前在编译时设置。
七个音符键已完成固定独立声部接入，第八键选择压力表达模式，歌曲与触摸可并行。后续若验收 ≤10ms，应使用实测满足要求的演奏输入。
统一使用 `PCM5102_PAM8403.gprj`，下载文件仍为 `PCM5102_PAM8403.fs`。
历史诊断版本保留在 `debug/` 中。显示屏等附属功能在音频核心验收后集成。

当前数字验证已覆盖四音并发、独立尾音及变调；用户已确认前两步完成。本轮四声部尚未进行 DAC/功放模拟输出测量。

## 5. 计划模块

- `note_event.v`：实时输入同步、音符开关及参数事件。
- `voice_allocator.v`：第四步加入动态声部分配；当前四个固定槽位已支持独立控制。
- `dds_voice.v` / `sine_rom.v`：独立相位和逐样本数学波表合成。
- `adsr_env.v`：逐声部硬件包络。
- `synth_voice.v` / `poly_synth.v` / `audio_mixer.v`：已实现四路封装与混音、固定缩放及饱和。
- `top.v`：连接现有采样节拍、I2S 与新声部引擎。

仿真重点检查可变音高、四声部独立性、ADSR 时序、数值边界、快速重触发、I2S 格式和最坏相位下的事件到样本延迟。最终用逻辑分析和 DAC 模拟输出测量确认整体延迟。
