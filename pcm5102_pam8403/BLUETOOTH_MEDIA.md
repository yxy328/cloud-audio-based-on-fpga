2026-10-15 修正：赛题要求由 FPGA 根据实时演奏指令逐音、逐样本生成音频，基础复音数至少 4，支持实时变调、ADSR 和混音，禁止预录 PCM 播放、预置推流和整段录音触发。
此前 MP3/FLAC 转 PCM 下载试听的路线违反这项要求，已撤回；旧位流 **UserCode=0x00009C48 不用于比赛或本轮验收**。修正后的构建状态见 [验证记录](VERIFICATION.md)。

PCM5102 继续作为 DAC：`现场按键 → FPGA DDS / ADSR / 多声部混音 → I²S → PCM5102 → PAM8403 → 喇叭`。
这里的 PCM 是 FPGA 当场合成的数字采样，不是存储的录音。工程不再接受 `PCM_BEGIN`、`PCM_DATA`、`PCM_END`、`PCM_PLAY`、`PCM_STOP`，这些命令均返回 `ERR,CMD`。

继续使用 `PCM5102_PAM8403.gprj`、原 HC-05/PCM5102/PAM8403 接线和 9600/8N1。
命令使用大写 ASCII，以 LF、CR 或 CRLF 结束，一行最多 64 个字符。**每发一行，收到对应回复再发下一行。**

## 音符曲谱下载

```text
SONG_BEGIN,7
SONG_NOTE,0,60,500
SONG_NOTE,1,60,500
SONG_NOTE,2,67,500
SONG_NOTE,3,67,500
SONG_NOTE,4,69,500
SONG_NOTE,5,69,500
SONG_NOTE,6,67,1000
SONG_END
PLAY
```

逐行等待 `OK`。数据表示《小星星》第一句的音符和时长，不包含音频采样。

| 命令 | 含义 |
| --- | --- |
| `SONG_BEGIN,7` | 开始暂存 7 条音符记录 |
| `SONG_NOTE,0,60,500` | 索引 0：MIDI 60，持续 500ms |
| `SONG_CHORD,0,145,500` | 索引 0：C4+E4+G4，持续 500ms；145 为十进制音高位图 |
| `SONG_CHORD,1,0,250` | 索引 1：休止 250ms |
| `SONG_END` | 检查全部记录、时长和当前键位覆盖，成功才提交 |
| `PLAY` | 预备 1500ms 后开始已下载曲谱的七轨屏幕指引；默认不自动发声 |
| `STOP` | 停止曲谱时序；现场按键仍独立发声 |

支持 1～128 条记录；索引从 0 开始，MIDI 为 60～72，每条 1～60000ms。
`SONG_CHORD` 的音高位图为 **十进制 0～8191**，bit0 对应 MIDI60，bit12 对应 MIDI72；它与 `EVT` 的七键十六进制位图不同。
和弦为同一时段内应保持的音高集合；零位图为休止。所有记录按时长顺序串接，音符和和弦命令可以混用。
按索引覆盖，允许乱序及重发；缺记录返回 `ERR,MISSING`，所需音符未映射到任一键返回 `ERR,MAP`。
范围错误返回 `ERR,RANGE`，未开始下载或没有有效内容返回 `ERR,STATE`。
修改映射后 `PLAY` 重新检查覆盖。下载时停止曲谱、松开音符键并结束录制，否则可能返回 `ERR,BUSY`。

曲谱使用暂存/有效双银行，`SONG_END` 成功才替换旧谱；中途断开蓝牙或检查失败保留原有效曲谱。
断开蓝牙后 FPGA 仍可推进曲谱并响应现场弹奏；**RAM 内容掉电丢失**。需要掉电保存时保存音符事件和配置，不能借外部存储改成录音播放路线。

生产默认 `top.ENABLE_DEMO_SCORE=0`，曲谱音符不会自动进入发声通路。有有效下载谱时，S1 开始/停止曲谱时序，S2 从头重启；无有效下载谱时，S1/S2 不动作，`PLAY` 返回 `ERR,STATE`。
主动改为 1 后才允许曲谱合成试听及内置《小星星》演示；该模式仅供开发，不能替代实时演奏验收，也不据此声称整机合规。单键按住时可实时变调，复音时 FSR 统一影响七键；各声部 ADSR 实时运行，A/D/S/R 参数目前编译期配置，尚无运行时设置命令。

## 演奏记录

`REC_START` 返回 `OK` 后，先输出当前键位 `MAP,...`，再输出时间为 0 的初始状态：

```text
MAP,60,62,64,65,67,69,71
EVT,0,00,0,39321,65535
EVT,120,01,0,39321,65535
EVT,650,00,0,39321,65535
```

`EVT` 字段依次为：相对开始的毫秒时间戳、七键十六进制位图、压力模式、实际音量系数、实际音高比例。
位图 `01` 为键 1，`03` 为键 1+2，`40` 为键 7；压力模式 0 为音量、1 为音高。
时间取去抖后状态变化时刻，包含现有防抖延迟。上例表示键 1 从 120ms 按到 650ms，持续 530ms。
音量系数示例仅为格式说明，实际值随当前控制状态变化。

按键变化按 FPGA 时钟检测；压力每 20ms 检查，仅变化时记录。长按且状态不变不会重复上传。
系数为 16 位整数，65535 表示该路径全比例；记录的是控制事件，不是麦克风录音或 PCM 音频。

`REC_STOP` 先返回 `OK`，然后排空缓存、发送停止时的最终 `EVT`，最后输出 `REC_END,0`。
等待结束标记后再导出日志或开始下一次录制。录制及尾部排空期间拒绝 `MAP`/`MAP_RESET`。
64 条 FIFO 缓冲 UART 来不及发送的变化；溢出时发送 `ERR,REC_OVERFLOW,<累计丢失条数>`，
`REC_END,<累计丢失条数>` 同时给出完整性结果。即使 FIFO 满，最终状态仍由独立槽保存。
9600bps 吞吐有限，FIFO 只能缓冲突发；出现溢出不能认为记录完整。

日志可保存/复制用于分析、指导或后续重放开发；手机端声音重建尚未实现。预存事件的自动回放不能替代赛题要求的现场实时演奏。

## 安卓下载与 HUB75E 音游指引

安卓 App 见 [安装与使用](android_app/README.md)。继续用已配对的 HC-05，无需蓝牙音频模块；App 可选内置《小星星》或导入 CSV/标准 MIDI 0/1，核对七键映射后逐行等待确认，提交成功才显示下载完成。
这里的“在线曲谱下载”已实现手机文件经 HC-05 下载到 FPGA RAM；首版没有互联网曲库服务。

生产顶层接入 `hub75e_rhythm_display.v`，驱动现有 **64×64、1/32 扫描** HUB75E 屏。七轨从左到右对应键1～7，音符提前1500ms下落，y=54为判定线，底部显示实际按键。
当前目标显示橙色，按键反馈为绿色，与目标一致时为白色；首版没有分数、命中判定或长音尾条。
音符间距小于一像素（约29ms）时同列合并显示；曲谱毫秒时序和按键目标仍逐条推进。扫描、串口、音频共用50MHz主时钟，互不等待。
完整屏幕接线和验收见 [RHYTHM_GUIDE.md](RHYTHM_GUIDE.md)。
MP3/FLAC 不能直接提供准确的音符谱面；需要人工制谱或离线转谱后逐项校对音高、起音和时长，再下载音符事件。
