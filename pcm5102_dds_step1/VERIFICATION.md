## RTL 仿真

工具：Icarus Verilog，Verilog-2001。

- 正弦 ROM 的 1024 个完整周期地址与独立数学正弦参考比较，通过。
- DDS 的 8203 次更新/保持检查通过，覆盖四个实时音高、相位回绕、运行中改变步进、采样使能暂停、零步进和复位。
- 按键过滤检查通过：短按/短释放抖动被忽略；长按只产生一次事件；释放后再次按下产生新事件。

## 布局布线后的功能仿真

使用 `impl/pnr/DDS_STEP1.vo` 与 Gowin 的 GW5A `prim_sim.v`。
没有标注 SDF，因此这是功能仿真；硬件时序另由静态时序报告检查。

仿真仅从顶层 BCK/LRCK/DIN 解码，无需读取发送机内部样本寄存器。
RTL 与网表测试均获得 3985 个完整左右声道对，左右样本一致。
验证 BCK 周期 320ns、LRCK 周期 20,480ns、每声道 32 位、一拍延迟、MSB 优先、补零和下降沿更新。

## 现场版本排查与 SRAM 下载

用户报告按 S2 音高没有变化后，通过下载器 Location 385 读取开发板：

- 初始 UserCode：`0x00007A8C`，与旧 `pcm5102_pam8403/impl/pnr/PCM5102_PAM8403.fs` 一致。
- 新变调版位流头部 UserCode：`0x00005C06`。
- 旧顶层只有 S1 输入，没有 S2 或音高选择逻辑。
- 下载本工程 `impl/pnr/DDS_STEP1.fs` 到 SRAM 成功。
- 下载后回读：UserCode `0x00005C06`，Status `0x70026020`，设备 ID `0x0001281B`。

第一次新版本下载后，用户反馈仍未变调。再次回读发现板上又变回 `0x00007A8C`。
用户随后确认在 Programmer 中再次下载过；检查图形界面的 FS File 栏，确实仍指向旧的
`pcm5102_pam8403/impl/pnr/PCM5102_PAM8403.fs`。

已在 Programmer 的 Device configuration 中将文件改为本工程 `DDS_STEP1.fs` 并保存。
从该图形界面再次执行 SRAM Program 成功，窗口输出 UserCode `0x00005C06`、Status `0x70026020`、Finished。
CLI 独立回读也确认 UserCode `0x00005C06`，避免“命令行下载新程序、图形界面随后又覆盖旧程序”。

下载日志：`programmer_sram.log`；最新独立回读日志：`programmer_verify.log`。
