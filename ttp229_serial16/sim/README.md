# 自检仿真

在工程上级目录运行：

```powershell
& ./ttp229_serial16/tools/run_sim.ps1
```

脚本优先使用 `C:/iverilog/bin/iverilog.exe` 和 `vvp.exe`，编译 SystemVerilog
测试平台与实际 `src` 中三个 Verilog 模块。任一检查失败即 `$fatal` 并让脚本报错；
成功输出 `ALL TESTS PASSED`。编译产物和运行日志保存在 `sim/build/`。
需要波形时加 `-Vcd`，波形同样写入 `sim/build/`。

测试包括：

- TTP229 外部行为模型：有效 SCL 边沿推进 D0～D15，SDO 在边沿后延迟
  350 ns 才变化；首边沿锁定完整触摸位图；只有超过 2 ms 的间隔才重置位序。
  FPGA 复位不会直接重置该传感器模型。
- 低有效和高有效分别验证 69 个完整帧，逐个检查全部 16 位（含 K16）、
  无键、多键和全键，检查 16 个时钟脉冲、半周期、帧间隔、启动等待、
  `frame_valid` 单拍以及每周期的按下/松开事件。
- 用独立帧级参考计数器验证每个键连续三个不同帧才能改变状态；覆盖不足
  三帧的毛刺、按下/松开计数被中断、其他键抖动时独立确认、长按没有重复事件。
- 一帧中途改变触摸输入，检查锁帧；一帧读到第七位时复位 FPGA，检查等待
  超时后重新从 K1 对齐，以及滤波状态清空。
- 在真实 50 MHz 时钟下检查生产默认高有效模式的 10 us 半周期、完整 16 脉冲、K16
  和 10 ms 帧间隔计数。此子测试仅把启动等待加速到 3 ms。
- UART 通过外部 TX 引脚逐位按 8N1 接收，检查大写十六进制、CR/LF、
  报告期间输入变化不会破坏已冻结的报文以及 `ready` 低时保持空闲。
- 顶层检查当前高有效默认配置、无需外部复位的上电复位、确认按键点亮 LED、松开后熄灭 LED、
  运行 LED 在 250 ms/500 ms 转换，以及实际 TX 的按下/松开报告。

仿真使用 1 MHz 整倍频时钟和加速的 3 ms 启动等待；帧间隔仍大于协议
要求的 2 ms。它验证数字逻辑与所建模的协议，不能代替模块 TP 配置、
电源、接线、引脚分配和实际触摸环境的板上检查。生产工程启动等待为 1 s。
