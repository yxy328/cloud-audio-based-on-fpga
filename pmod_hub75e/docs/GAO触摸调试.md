# 没有 LED 屏时，用 GAO 观察触摸

只连接 Tang Primer 25K 和 TTP229 即可。ROM、扫描逻辑、触摸读取和交互状态仍照常运行。

## 当前主位流及已验证的修复

当前使用 `impl/pnr/ao_0.fs` 与 `src/HUB75E.gao`，下载校验值为 **0x2187**，
GAOCRC 为 **1010001010110110**。这对文件已实际下载（Finished，5.46 秒），F3 强制触发能显示波形。
当前实测原始/稳定键值仍为 `0000`、SDO 为高，**尚未验证触摸键 1 成功**。

已确认此前代码的 S1 复位极性错误。
[Dock 60033 官方原理图第 1 页](https://dl.sipeed.com/fileList/TANG/Primer_25K/02_Schematic/Tang_Primer_25K_Dock_60033_Schematic.pdf)
中，S1 按下将 H11 接到 3.3V；松开时需内部下拉。当前设置 `USER_KEY PULL_MODE=DOWN`、
`uresetn <= ~USER_KEY`。旧极性会在松开 S1 时保持业务复位，
原先随业务复位停止的分频器还会使 GAO 等待采集，强制触发也无法完成。

当前 `clkn` 自由运行，保证复位期间 GAO 时钟持续运行；
显示扫描单独使用 `scan_div`，业务复位时清零，保持扫描与同步 ROM 的初始化相位。
主 GAO 新增 `USER_KEY`，可直接核对松开为 0、按下为 1。
这个修复已通过仿真和实际强制采集验证，但不能据此宣布模块触摸读取已经正常。

## 打开及采集

1. 打开 `HUB75E.gprj`，当前 `src/HUB75E.gao` 已启用并配置完成。
2. 下载 **`impl/pnr/ao_0.fs`**，在 Gowin Analyzer Oscilloscope 加载配套 **`src/HUB75E.gao`**。
   配置和位流须来自同一轮构建；以前的 `HUB75E.fs` 不含当前分析仪配置。
3. 若重新构建，运行 `gw_sh tools/build.tcl`，或在 IDE 重新综合、生成 Post-Synthesis GAO、布局布线。
   重建后的校验值可能改变，请重新核对配置与位流。
4. 模块上电后先松开所有触摸键等待约 1 秒；驱动每次复位后保持 SCL 空闲 600 ms。
   修改模块跳线后需要完整断电重新上电。
5. 松开全部触摸键，点击 **Start（F1）**，轻触模块键 1 约半秒后松开。
   单次采集会保留按下波形，**不需要一直按住，更不需要用力压**。板上 S1 是复位键。
6. 想连续查看按下/松开，使用 **Auto Run（F2）**；其后续捕获会更新窗口。停止为 **F4**。

没有稳定键变化时，Start 等待触发属于正常状态。先确认采集是否工作，可点击
**Force Trigger（F3）**。强制采集成功不代表模块键值已经读对。

## 已保存的参数

| 参数 | 当前设置 |
| --- | --- |
| 采样时钟 | `clock=clkn[3]`，3.125 MHz，复位期间持续运行 |
| 显示扫描时钟 | `scan_clock=scan_div`，25 MHz，业务复位时清零 |
| 存储深度 / Capture Amount | 16384 |
| Segments Number | 1 |
| Trigger Position | 12288，即深度的 3/4 |
| Match Unit M0 | `gao_changed` 上升沿，Rising Edge |
| Trigger Expression | M0 |
| 采集信号位数 | 47，包含 `touch_scl`、`touch_sdo`、`USER_KEY` |

`gao_changed` 在稳定键值变化时拉高 20 μs，按下和松开均能触发，长按不重复触发。
原来的 `key_press` 只持续 20 ns，慢速 GAO 可能漏采，因此不直接用它作触发。
键值和交互状态在 50 MHz 主时钟下降沿统一快照；SCL、SDO、USER_KEY 直接采集。
综合时 SCL/SDO 若提示被替换为等效信号名，应核对映射，不能仅凭改名判定读键故障。

默认低有效时，SCL 空闲高、下降沿开始读位，在低电平末采样，半周期 50 μs。
16 位读完后保持高电平约 3.02 ms，包含 20 μs valid 和 3 ms 帧间静置；
连续帧的 valid 上升沿间隔约 4.57 ms。

## 按下后看哪些变化

将 `touch_keys`、`keys_stable` 设为十六进制显示，亮度设为无符号十进制。
这些是预期行为；当前实板触摸响应尚未通过。

| 操作 | `touch_keys` | `keys_stable` | 交互状态 |
| --- | --- | --- | --- |
| 按键 1 | `0000 → 0001` | 连续 3 帧相同后变 `0001` | `image_requested=1`，请求 S 图 |
| 按键 2 | `0000 → 0002` | 连续 3 帧相同后变 `0002` | `image_requested=0`，请求 T 图 |
| 按键 15 | `0000 → 4000` | 连续 3 帧相同后变 `4000` | 亮度从 8 降为 7 |
| 按键 16 | `0000 → 8000` | 连续 3 帧相同后变 `8000` | 亮度加 1，最大 8 |
| 松开 | 原始帧先回 `0000` | 连续 3 帧后回 `0000` | 图案/亮度保持，再产生 `gao_changed` |

初始为 T 图、亮度 8。按键 2 或 16 时，图案/亮度可能已经在目标值，但键值仍应变化。
成功判据是松开、按键 1、松开得到 **`0000 → 0001 → 0000`**，不能仅凭出现非零值判断。

`image_active`、`brightness_active` 在完整 PWM 周期边界更新，
可能比 requested 晚最多约 2.744 ms。默认采样窗口总长约 5.243 ms，
触发前约 3.932 ms、触发后约 1.311 ms。
三帧防抖确认跨度约 9.14 ms，因此窗口无法同时包含首次原始变化和完整防抖过程；
触发附近 `touch_keys` 可能已经是 `0001`。

active 也不保证在默认右侧窗口内完成更新。可在后续强制采集中核对，
或临时将 Trigger Position 改为 4096，得到约 3.932 ms 的触发后窗口。

## 没有出现变化时

- **等待触发**：先确认 `USER_KEY=0`，然后用 F3 核对采集。当前主位流修复了复位期间 GAO 时钟停止的问题。若强制采集正常而轻触不能自动触发，继续检查读帧数据，不能将等待本身视为软件卡死。
- **SCL 前半段一直高**：帧间本来有约 3 ms 的高电平空闲。横轴缩放到完整 16384 样点，并展开单 bit 波形后查看。只显示一小段，或左侧光标值为 1，不能证明整个捕获中没有低电平。
- **valid 有脉冲、键值一直 0000**：说明 FPGA 读帧状态机在运行。需查看完整 16 位读位期间的 SDO；全部为高与低有效译码 `0000` 一致，尚不能仅凭此定位模块、电平或协议的根因。
- **连接或读取 GAO 失败**：核对本次配置/位流、下载线及器件，尤其不要混用旧 LOW/HIGH/FRAME 配置。

此前模块拔掉后 F6↔F7 回环得到 `FFFF`，这支持 FPGA 输出和输入路径正常，
但回环不能验证真实 TTP229 的时序、复位或触摸响应。
如重复回环，必须先断电并拔掉模块，避免模块输出与 FPGA 输出相连；
F6/F7 是 FPGA 焊球号，不是排针第 6/7 脚。
SCL/SDO 能在 GAO 中被观察到，也不代表已测量模块端的实际电压。

本工程为 TTP229-BSF 双线 16 键、低有效模式：TP2 短接，多键需 TP3/TP4 都短接。
`TP_ACTIVE_LOW` 同时控制 SCL 和 SDO；高有效时空闲低、上升沿读位。
复位后等待 600 ms、帧间无边沿 3 ms，用于启动稳定和串口重新对齐。
这些机制依据 [Tontek 官方 TTP229-BSF 手册](https://www.tontek.com.tw/uploads/product/97/TTP229-BSF_V1.1_EN.pdf)；
已经仿真验证，不代表已解释当前实物持续 SDO 高的全部原因。
